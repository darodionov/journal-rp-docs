# B1 «Русскій Паломникъ» - инвентаризация HTML-разметки корпуса

Дата: 2026-08-24. Только чтение. Это разведка под словарь «тег -> правило» для стадий
S4-S5 (HTML -> MDX). Отчет НЕ принимает решений: графы «РЕШЕНИЕ» пустые, их заполняет владелец.

## Источник и метод

- Вход: `../journal/var/corpus.jsonl` - артефакт стадии S1 (в .gitignore). Использованы поля `id`, `body`.
- Строк в файле: **1345** (старая версия корпуса). По решениям от 2026-08-24 из анализа
  исключены id 4, 5, 6, 60, 1022, 1045 (все присутствуют в файле). Разобрано статей: **1339** = 1345 - 6.
  Примечание: id 4, 5, 6, 60 - это внешние `isext=1`-заглушки с пустым `body`; их исключение на инвентарь разметки не влияет.
- Парсер: стандартный `html.parser` (событийный токенайзер Python), устойчив к незакрытым
  и криво вложенным тегам - НЕ регулярные выражения. Имена тегов и атрибутов приведены к нижнему регистру самим парсером.
- «Спотыкания» разбора отслеживались стеком открытых тегов: висячие закрывающие,
  перекрытие неопциональных тегов, незакрытые неопциональные теги на конце тела.
- Товарная разметка (`/buy/`) считается отдельно (см. ADR-0009 - проносится без изменений). Признак buy: тег
  с `/buy/` в `href`/`src` либо любой его потомок; отдельно посчитаны теги-обертки (прямой родитель buy-узла).

Наблюдения верхнего уровня (для владельца, решений не содержат):

- Разметка почти вся **презентационная и редакторская**: `<span style=font-size:14px>` и красный
  `<span style=color:rgb(255,0,0)>` - крупнейшие источники шума (десятки тысяч вхождений). Кандидаты на снятие в S4.
- `<sup>` - **19 276** вхождений в 1110 статьях, 99% содержимого - чистые цифры: маркеры сносок/примечаний (надстрочные номера).
- Структурно корпус чистый: **1** спотыкание разбора на 1339 статей (один висячий закрывающий тег).
- В **10** статьях (id 23,24,25,27,47,49,50,51,53,59) в теле лежат литеральные `<style>` и рекурсивно
  многократно URL-кодированные комментарии `<!--{cke_protected}...-->` (мусор CKEditor). Из-за этого тело id 23
  раздуто до ~771 КБ. Так как `<style>` - CDATA-элемент, разметка внутри него и внутри `{cke_protected}` не
  токенизируется (это и не живая разметка) - но как объект чистки S4 это надо видеть.
- Ссылки `<a>` встречаются лишь в 139 статьях; из 410 якорей 164 ведут в магазин (`/buy/...`), остальные - в основном
  внутренние кросс-ссылки `/content/article/...` (~212) и ссылки на легаси-страницы `/htm/...` (~13), единичные внешние домены.
- Таблицы (`table/tr/td/tbody`) - ровно в 40 статьях; `<font>` (устаревший) - в 16.

## Машинный файл

Рядом лежит `tag-inventory.json` - те же данные целиком (в отчете стили обрезаны до топа).
Структура: объект с `meta` (счетчики, исключенные id, параметры) и массивами `tags`, `styles`,
`classes`, `entities`, `buy_wrappers`, `stumbles`. В каждом элементе `occ` - всего вхождений,
`arts` - в скольких разных статьях; у стилей есть готовое поле `hypothesis` (помечено `hypothesis_flag`)
для будущей сборки словаря S4. Сортировка массивов - по `arts` убыв. Точные ключи - в `meta.schema`.
