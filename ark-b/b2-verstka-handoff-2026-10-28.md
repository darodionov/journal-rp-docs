С 2026-10-20 работа ведётся двумя ветками. Ветка вёрстки — новый чат с
наставником, код пишет владелец руками: страница статьи (строка даты), ленты

страниц и шаг B5 (полный корпус) и идёт дальше по плану: B3 (кэш-теги), затем
B4 (мост редиректов).

Этот файл — передача ветки вёрстки. `ark-b/b2-handoff.md` он не заменяет:
тот описывает шаг B2 целиком и правится Claude Code; здесь — только то, что
нужно чату вёрстки. Читать первым.

Режим нового чата: `#учебник`. Код пишет владелец; наставник объясняет и
ставит задачу. Обратный порядок («делаешь ты», «пиши сам») — только по
явной просьбе на конкретную задачу. Квиз — только по команде `#квиз`.

### Что B5 меняет для вёрстки

1. **Ленты стали большими.** До B5 сайт стоял на 60 статьях, теперь на 1377.
   Крупнейшие ленты житий — порядка тысячи статей; при `PAGE_SIZE = 20` это
   десятки страниц. Нынешняя пагинация «Позже · N · Раньше» с таким объёмом
   не справляется: макет и вёрстка должны уметь номера страниц, текущую,
   пропуски и края. Это входное требование к макету пагинации.
2. **В статьях появились таблицы** (38 статей, подписи из ячеек) и намного
   больше спаренных сносок. Типографика тела статьи (`prose`) должна их
   держать: стили таблиц, блока сносок, обратных ссылок. Это не P6, а
   доводка страницы статьи; точный список — находки R7 в декомпозиции B5.
3. **Описания есть почти у всех.** У 124 статей описание взято из первого
   абзаца тела — бывает длинным; карточка должна обрезать его по строкам,
   а не по символам в данных. Вопрос «описание равно заголовку» (открытый
   вопрос 5) после B5 нужно перепроверить на полном корпусе.
4. **Обложки разных пропорций** — горизонтальные и вертикальные, и у
   многих статей обложки нет вовсе. Карточка обязана уметь все три случая.
5. **Длинные и дореформенные заголовки** (капс у части журнальных H1,
   «партийные» заголовки житий) — карточка проверяется на худшем случае, а
   не на образцовом.
6. **Глаза R7 — последний пункт ветки вёрстки.** После лент, хабов и
   главной владелец проходит список находок R7 из декомпозиции B5 и
   отмечает каждую.
7. **Соседство с B3.** Claude Code в B3 правит адаптер контента и кэш
   (`src/lib/content/filesystem-source.ts`, точка входа `index.ts`). Ветка
   вёрстки трогает `src/lib/content/labels.ts` (строка даты) — перед
   коммитами убедиться, что сеанс Claude Code не держит то же рабочее
   дерево и не правит тот же файл.

### В каком виде передавать

**Картинка — PNG в масштабе 1:1.** Ширина артборда ровно 1600, 768 или 320,
без масштаба браузера и без рамок интерфейса. PNG, а не JPG: JPG шумит на
тонких линиях, и замеры статьи уже страдали погрешностью ±1–4 px из-за
этого.

**Длинный макет — резать по высоте.** Перед тем как наставник видит
изображение, оно уменьшается, если длинная сторона больше примерно 1500
пикселей: макет 1600 × 7400 сжался бы до нечитаемого. Поэтому: куски
шириной 1600 и высотой до 1200–1500 px, с перекрытием около 100 px, имена
по порядку (`lenta-1600-01.png`, `lenta-1600-02.png`, …), плюс одна
уменьшенная обзорная картинка целиком — для понимания композиции. Для 320
и 768 то же правило по высоте.

**Код — выгрузка Claude Design (`.dc.html`) вложением.** Это эталон чисел:
ширины, отступы, кегли, цвета и имена токенов. Не код для переноса:
прототипы Claude Design держат приёмы, которые в проект не идут (амендмент
ADR-0004 от 2026-08-09 называет в `Статья.dc.html` `margin-left: -330px` и

### А.1. `src/lib/content/labels.ts` — в конец файла

```ts
/**
 * Дата для читателя: «18 октября 2026 г.». Строку `ГГГГ-ММ-ДД` движок
 * разбирает как полночь UTC, поэтому и форматировать её надо в UTC: иначе
 * сборка на машине западнее Гринвича покажет 17 октября. Форматтер создаётся
 * один раз на модуль — построение Intl-объекта не бесплатно.
 */
const DATE_FORMAT = new Intl.DateTimeFormat('ru-RU', {
  day: 'numeric', month: 'long', year: 'numeric', timeZone: 'UTC',
});

export const dateLabel = (isoDate: string): string => DATE_FORMAT.format(new Date(isoDate));
```

### А.2. `src/components/article/article-dateline.tsx` — новый файл

```tsx
import Link from 'next/link';
import { isMigrated, isRusskiyPalomnik, type ArticleMeta } from '@/lib/content';
import { dateLabel, vypuskLabel } from '@/lib/content/labels';
import { zhurnalNomerPath } from '@/lib/routes';

/**
 * Строка выходных данных статьи — правило P5.6 декомпозиции B2.
 *
 * Рукописная статья заявляет дату публикации. Мигрированная — нет: её
 * `datePublished` — дата правки на старом сайте или посев сортировки
 * (ADR-0004-m), и выдавать её за дату публикации значило бы солгать.
 * Статья журнала вместо даты показывает выпуск со ссылкой на ленту номера;
 * остальные мигрированные строки не имеют.
 *
 * Текст строки — сервисный, поэтому в современной орфографии (принцип 04
 * дизайн-гайда): дореформенное письмо — для логотипа и исторических
 * заголовков. Стиль строки — решение владельца; `not-prose` выводит её из-под
 * типографики тела статьи, иначе она получила бы стили абзаца.
 */
export function ArticleDateline({ meta }: { meta: ArticleMeta }) {
  if (!isMigrated(meta)) {
    return (
      <p className="not-prose">
        <time dateTime={meta.datePublished}>{dateLabel(meta.datePublished)}</time>
      </p>
    );
  }

  if (isRusskiyPalomnik(meta) && meta.magazineNum !== undefined) {
    return (
      <p className="not-prose">
        Журнал «Русский Паломник»,{' '}
        <Link href={zhurnalNomerPath(meta.magazineNum)}>{vypuskLabel(meta)}</Link>
      </p>
    );
  }

  return null;
}
```
