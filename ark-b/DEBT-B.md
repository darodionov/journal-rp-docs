# DEBT-B.md — техдолг и напоминания арки B (конвейер миграции)

> **Протокол (для людей и для Claude).**
> Одна строка = одна запись. Формат: `- [ ] ГГГГ-ММ-ДД #тег текст`
> Тег — шаг арки (`#B1`…`#B6`), либо `#C` (передача в арку C), `#tooling`,
> `#docs`, `#data` (легаси-БД, дампы, кодировки), `#напоминание`.
> Сделано → меняем `[ ]` на `[x]`, строку не удаляем (история решений).
> Новое дописываем **в конец** соответствующего раздела.
>
> **Разделение с `DEBT.md`:** здесь — только арка B (конвейер, легаси-данные,
> редиректы) и передачи из неё в другие арки. Всё остальное (арки A/A′, дизайн,
> тулинг приложения) остаётся в `DEBT.md`. Строки не дублируем: запись живёт
> в одном файле; при переносе — `[x]` со словом «→ DEBT-B.md» в исходном.
>
> **Факты о данных живут не здесь**, а в `design/legacy-data-facts.md`:
> долг — задача с моментом закрытия, факт — знание, которое не закрывается.
>
> **Команды в чате:**
> — «запиши на память …» / «запиши напоминание …» → Claude формулирует готовую
>   строку в этом формате; вставляет владелец или Claude Code.
> — «что в долгах по B?» / «покажи долги по B1» → Claude ищет этот файл в
>   знаниях проекта и выдаёт актуальный список (при необходимости с фильтром).
> — просьба ИЗМЕНИТЬ документ (этот или любой другой) → Claude останавливается
>   и просит прикрепить нужные файлы поимённо: knowledge и привязанный GitHub
>   отдают только фрагменты по поиску, полноты текста не гарантируют, и версия
>   «по памяти» была бы выдумкой (правило 2026-08-29). Дописать одну строку
>   можно без вложений — переписать документ нельзя.
>
> **Важно:** файл должен лежать в репозитории **и** быть добавлен в knowledge
> этого Project — иначе чаты его не увидят. После правок — пересинхронизировать
> проект, иначе Claude читает устаревший снимок.
