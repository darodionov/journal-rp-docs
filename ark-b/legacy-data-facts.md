# Факты о легаси-данных

Что **проверено запросами к базе**, а не взято из документации. Одна строка =
один факт + следствие для конвейера. Факты не «закрываются» — они уточняются;
задачи из них живут в `DEBT-B.md`.

Источник: легаси-БД (дамп 2018-11-17), MySQL 5.7, проверено 2026-08-22.
Расхождения с `legacy-map.md` / `legacy-rubrics.md` — приоритет у этого файла.

## Схема articlex

- Тело статьи — **`body`** (mediumtext). Поля `pg_txt` **не существует**;
  так оно названо в старых заметках и в первой редакции карты стадий.
- `anons` (text) — **пусто во всей таблице**. Из конвейера исключено;
  единственный источник `description` — `pg_dsc`.
- `url` (varchar 60) — легаси-слаг физически ≤ 60 символов, тогда как
  ADR-0009 разрешает генерируемым до 80.
- `pg_ttl` (varchar 200), `pg_dsc` (varchar 300), `pg_kwd` (varchar 120).
- Флаг публикации — **`is_close`** (tinyint(1), NOT NULL, default 0),
  инверсный: 1 = статья снята.
- Ссылки в подвале: `footer_lnk_1..3` + `footer_url_1..3`; у статьи ещё
  пара `lnk` / `url`. Встроенное видео — `youtube` (varchar 20).
- Даты в таблице: `dt1..dt3_day/month` — **дни памяти святых** (до 3 на
  статью), `days_easter` — смещение от Пасхи, `last_date` — дата правки.
  **Даты публикации в схеме нет.**

## Корпус и типы

- Всего записей `articlex` — **1662** (совпало с контрольным числом импорта).
- Классификация 23 типов полна: корпус 1523 + оглавления 40 + служебное 99.
- Корпус B1 после вывода именинного куста (типы 14, 15, 18 → арка C) —
  **1345** статей: типы 1, 2, 3, 4, 5, 6, 17, 20, 26.
  Проверка сложением: 1199 + 66 + 32 + 18 + 18 + 8 + 2 + 1 + 1 = 1345.
- Раскладка в конвейере — **четыре корзины**, а не три: CORPUS (1345)
  конвертируется в B1; DEFERRED (14, 15, 18 — 178 статей именинного куста)
  отложено в арку C; TOC (40) станут генерируемыми списками; SERVICE (99)
  не мигрируется никогда. Различие DEFERRED и SERVICE смысловое:
  отложенное ≠ отброшенное. Неизвестный тип = смерть прогона S1.

## Публикация

- Закрытых статей — 13, все **вне корпуса**: тип 0 — 1, тип 8 — 11,
  тип 16 — 1. → Поле `draft` в схеме A4 **не требуется**; проверка
  `is_close` в S1 остаётся сторожевой, а не фильтрующей.

## Даты

- `last_date`: минимум `0000-00-00 00:00:00`, максимум `2024-03-24`,
  нулевых значений — **400**. → Как дата публикации **непригоден**:
  это дата правки, поздние годы относятся к жизни сайта, а не к написанию.
  Вопрос даты фронтматтера остаётся открытым (см. DEBT-B).
- `0000-00-00 00:00:00` — не NULL и не валидная дата (особенность MySQL).
  Драйвер обычно отдаёт `null`; поведение проверить глазами при выборке.

## Заголовки

- Хвост `… | <название рубрики>` в `pg_ttl` — у **1219** записей из 1662:
  жития 1150/1199, Добротолюбие 65/66, обычные статьи 4/32, прочие — 0.
  → Правило нормализации формулируется по факту наличия черты, не по типу.
- Оставшиеся 49 житий: обрезки НЕТ (максимум 148 символов при лимите 200).
  У них другая конвенция — склейка через точку: «Имя, чин. Житие <того же
  в родительном падеже>». Идентификаторы кучкуются (1412, 1450, 1454–1463,
  1595, 1596) — единая партия заливки (западные святые Оверни, Трира).
  → Отрезать по точке НЕЛЬЗЯ: точки есть в сокращениях (`о.`, `Преп.`,
  `ч.1`). Решение по этим 49 — отдельное, не общим правилом (см. DEBT-B).
- В заголовках встречаются опечатки и сбитый регистр (`отеца`,
  `в ангулеме`, `Сенапариистока`). Конвейер не чинит — выносит классом
  в отчёт.
- Заголовки старого журнала (`articles`) — в дореформенной орфографии
  (`Адрiанъ`, `Патерикъ`, `Валаамскiй`): подтверждает шаг «дореформенные
  буквы → современные» из ADR-0009 п. 3б.

## Ссылки

- Подвальные ссылки почти не используются: `footer_url_1` — 1 запись,
  `footer_url_2` — 1, `footer_url_3` — 0. → Правило в S7 не нужно,
  достаточно точечного решения по двум статьям.
- Пустой слаг (`url = ''`, не NULL) — 2 записи: id 1226 и 1545, обе type=4.

## Старый журнал (articles, 39 статей)

- Схема: `num` (PK), `date` (тип date, **настоящая дата публикации**,
  диапазон 2005–2008), `magazine_num` (tinyint unsigned — номер печатного
  выпуска), `title` (varchar 90), `column` (рубрика), `is_open`.
- Корпусу `articlex` дат не даёт — таблицы независимы.
- Флаг публикации `is_open` — **прямой**, в отличие от инверсного
  `is_close` в articlex. Не перепутать направление.
- `magazine_num` подозрителен по краям: 0 у трёх статей (номер не указан),
  255 у num=35 — ровно максимум tinyint unsigned, возможно «заглушка».
  Проверить глазами при переносе архива (арка C).

## Поведение драйвера (mysql2) — проверено на этой базе

- Агрегаты (`SUM`, `COUNT` через DECIMAL) приходят **строкой**, не числом:
  перед сравнением приводить `Number(...)`. Вычисляемым колонкам всегда
  давать `AS`-псевдоним, иначе имя поля — сырой текст выражения.
- `tinyint(1)` может прийти как 0/1 или true/false в зависимости от
  настроек соединения — проверять глазами, не предполагать.
- Кодировка решена на границе драйвера: сервер сам перекодирует cp1251 →
  utf8mb4 соединения; внутри программы — обычные строки JS, перекодировать
  в коде ничего не нужно.

## Как перепроверить (перед B5, на свежем дампе)

```sql
SELECT COUNT(*) FROM articlex;
SELECT type, COUNT(*) AS total, SUM(pg_ttl LIKE '%|%') AS with_pipe
  FROM articlex GROUP BY type ORDER BY total DESC;
SELECT type, COUNT(*) AS cnt FROM articlex WHERE is_close = 1 GROUP BY type;
SELECT MIN(last_date), MAX(last_date),
       SUM(last_date = '0000-00-00 00:00:00') FROM articlex;
SELECT SUM(footer_url_1 <> ''), SUM(footer_url_2 <> ''),
       SUM(footer_url_3 <> '') FROM articlex;
SELECT COUNT(*) FROM articles;
```
