# CMS: три точки приземления

Связано с ADR-0003. Актуально, когда контент начинают создавать/редактировать не-технические
авторы (журналисты, редакторы) — триггер переезда с MDX-в-репозитории на headless-CMS. Доставка
при любом варианте остаётся статической (webhook + ISR); меняется только источник истины за
абстракцией источника контента.

## Оси сравнения
Опыт редактора · роли и процесс (черновик→ревью→расписание→публикация) · где живут данные и
владение · связность со стеком (Next + Postgres + Drizzle + pgvector) · стоимость миграции с
MDX · модель цены · операционная нагрузка.

## Сравнение

| Ось | git-based слой (Keystatic/Tina/Decap) | Payload (self-host) | Sanity / Storyblok (SaaS) |
|---|---|---|---|
| Опыт редактора | базовый | хорошая React-админка | лучший, real-time совместный |
| Роли и процесс | слабые | есть (часть — в enterprise) | сильные |
| Хранение / владение | MDX в git (твоё) | твой Postgres (MIT, без лока) | их облако |
| Связность со стеком | максимальная (это тот же MDX) | максимальная (Postgres via Drizzle; pgvector рядом) | слабее (контент вне Postgres) |
| Миграция с MDX | почти нулевая | средняя (импорт MDX → коллекции) | средняя (импорт в их модель) |
| Цена | инфраструктура | инфраструктура (без per-seat) | per-seat / usage, растёт с командой |
| Операционка | нулевая | на тебе (бэкапы, миграции, холодные старты админки) | нулевая |

## Кратко по каждому

**git-based слой** — дружелюбный UI поверх существующего MDX, коммитит за автора «за кулисами».
Дешевле всего, сохраняет версионирование, миграция почти нулевая. Потолок: слабые роли,
расписание, одновременное редактирование, тяжёлые медиа. Временная мера для крошечной редакции
с простым процессом — не решение для настоящей редакционной команды.

**Payload** — self-host, TS-native, живёт внутри Next-приложения; Postgres через Drizzle.
Максимальная связность с нашим стеком: тот же Postgres и Drizzle, туда же ложится pgvector для
RAG (контент и вектора в одном хранилище). MIT, данные твои, без per-seat и вендор-лока. Конфиг
и схема — обычный TypeScript в репозитории кода (не нарушает «чистый код» — он и есть код). Цена:
операционка на тебе (бэкапы, миграции схемы; на serverless админка вялит из-за холодных стартов —
лечится VPS/контейнером или пулингом Neon). После покупки Figma Payload Cloud закрыт для новых
проектов, self-host — единственный путь, но MIT и открытый код сохранены. Сильный портфолио-сигнал.

**Sanity / Storyblok** — SaaS: лучший из коробки редакторский опыт и real-time совместность при
почти нулевой работе с бэкендом. Цена: контент в их облаке (отрывается от Postgres → для RAG нужен
экспорт/синхронизация), per-seat растёт с командой, вендор-зависимость.

## Перевес для этого проекта
Payload — из-за связности с Next + Postgres + Drizzle + будущим pgvector, владения данными и
портфолио-сигнала. Альтернатива — Sanity, если редакторский опыт и real-time станут доминирующим
приоритетом, а держать инфраструктуру не хочется. Правило: нужен нулевой вендор-лок → Payload;
приоритет — редакторский опыт и совместная работа → Sanity. Конкретный продукт выбираем, когда
триггер сработает (см. ADR-0003).
