# Конвейер B1: требования и болячки легаси (спецификация конвертера)

Дата: 2026-07-17. Контекст: шаг B1 `learning-build-plan.md`. Факты: 
`legacy-dump-checks.md` (articlex, дамп 2018-11-17), скан всех 39 выпусков
старого журнала (`legacy/pages/article/all/`, метод - cp1251-декод + regex по
`index.htm`/`*.htm`/`!.ogl`), образцы `extracted/`. Нейминг значений и типов -
по принятому ADR нейминга домена; слаг-политика и legacyId - по ADR слагов.

## 1. Требования к конвейеру B1

### 1.1 Границы, вход, выход
- Две ветки входа, один формат выхода:
  - **B1а (articlex)**: секции таблиц из дампа (потоковое выделение, дамп
    целиком не читать). Подвыборка B1 - 15-20 разнотипных статей; полный
    корпус 1523 - шаг B5 тем же кодом.
  - **B1б (старый журнал)**: 39 папок с диска. Обходить только `1..39`;
    `0`, `-10`, `av/`, `template.htm` - не контент.
- Выход: MDX с фронтматтером по Zod-схеме A4 + медиа рядом. Легаси и дамп -
  только чтение. Выход - только в content-дерево ../journal.
- `legacyId` обязателен в каждом фронтматтере: `id` articlex / `num` выпуска.

### 1.2 Кодировки (жесткие правила)
- Дамп: байты **UTF-8** (DDL `cp1251` описывает хранение в БД, не файл дампа).
  Мозаика `РџСЂ...` на выходе = декодировали неправильно, стоп.
- Диск (B1б): **cp1251 -> UTF-8 строго без -c** (реш. 3 дополнения к плану):
  непреобразуемый байт - ошибка файла в отчет, никаких молчаливых замен
  и потерь символов.
- Выход: UTF-8 (NFC). Numeric entities дореформенных букв переводить в
  юникод-символы (`&#1123;` -> `ѣ`). Орфографию НЕ модернизировать.

### 1.3 Идемпотентность и детерминизм
- Повторный прогон на том же входе дает байт-в-байт тот же выход:
  стабильный порядок обхода, без временных меток в выходных файлах.
- Выход - генерат. Ручные правки в выходных MDX запрещены (сотрутся
  перегенерацией). Точечные исправления - через файл оверрайдов конвейера
  (вход, версионируется рядом с конвейером).
- Режим dry-run: полный прогон с отчетом, без записи.

### 1.4 Валидация и отчет
- Контрольные числа до старта: корпус articlex 1523, выпусков 39.
  Не сошлось - стоп, чинить парсер, не продолжать.
- Каждый выходной MDX проходит Zod-схему фронтматтера; невалидный - ошибка.
- Ошибка на одном документе не валит прогон: документ в отчет, exit code
  ненулевой. Молчаливых пропусков нет - все, что не сконвертировано,
  перечислено поименно с причиной.
- Отчет: счетчики по рубрикам; entities; ссылки (переписано / оставлено /
  битые); картинки (перенесено / без alt / без размеров); оверрайды
  примененные; расхождения источников метаданных.

### 1.5 Ссылки (правила перезаписи)
- `-lib<id>` (1024 в корпусе) -> карта `id -> новый URL`; 628 из них ведут
  на оглавления - целями должны быть генерируемые списки B2.
- `article.php?article=N` (межвыпусковые в старом журнале) -> новые URL
  архива.
- `jurnal.php?name=&num=&page=` (пагинация №30) -> якоря/главы новой статьи.
- Магазин (`/buy/`, `show_item.php` в т.ч. относительной формой) - по
  отдельной политике (открытый вопрос, п. 4).
- Абсолютные `https://idrp.ru/...` -> относительные.
- Битых внутренних ссылок в легаси нет (проверено) - появление битой после
  конвертации означает ошибку конвейера, в отчет как ошибку.

### 1.6 Медиа
- Картинки копировать по конвенции контент-дерева, исходный легаси-путь
  фиксировать во фронтматтере/отчете.
- Размеры обязательны (next/image): брать из атрибутов, иначе из
  inline-style (articlex), иначе измерять сам файл (старый журнал).
- alt: легаси-значение если есть; политика для пустых - открытый вопрос п. 4.
- Неиспользуемые файлы папок выпусков не переносить, перечислить в отчете.
- `art.jpg` выпуска (есть у всех 39, в теле не упоминается) - это превью
  списка: кандидат в `cover` фронтматтера.

### 1.7 Метаданные (источники и приоритет)
- articlex: поля БД. `pg_ttl` 100%, `pg_dsc` 96.5% (для пустых - генерация
  на конвейере), `anons`/`youtube` пустые - игнорировать. Даты: `0` и `NULL`
  нормализовать в "нет значения"; `days_easter` - отдельная форма даты.
- Старый журнал - слить ТРИ источника: БД `articles` (date, magazine_num,
  title, column) + `!.ogl` (номер-год выпуска, рубрика, заголовки, дата
  памяти) + `<META>` в теле (4 выпуска). Конфликт значений - правило
  приоритета (предложение: БД для машинных полей, `!.ogl` для заголовков)
  и строка в отчете. Сверять `magazine_num` БД с номером из `!.ogl`
  (у №4 сходится: 2 == "№2-1990").

## 3. Болячки articlex (сводно; детально - `legacy-dump-checks.md`)

Для полноты спецификации B1а, по номерам проверок дампа:

- байты дампа UTF-8 при DDL cp1251 (метод);
- слаг не уникален: `zhitiya-svyatih` x1153, еще 8 групп дублей; 2 статьи
  корпуса без слага -> слаг-политика + legacyId (ADR слагов);
- даты: `0` и `NULL` вперемешку в dt-полях; 2 переходящих (`days_easter`,
  без фиксированной даты); 6 житий вовсе без дат (п. 5 rubrics-taxonomy);
- HTML-entities в заголовках/полях БД - декодировать;
- `anons` пуст у 100% корпуса, `youtube` пуст - игнорировать;
- grid-композиция: 2 случая, доноры - служебные фрагменты; по решению
  владельца механика переносится - конвейер фиксирует эти 2 связи в отчете;
- картинки: размеры в inline-style, а не атрибутах; 414 `/buy/`-превью -
  судьба вместе с магазином; ~355 редакционных JPG;
- ссылки корпуса: 1024 `-lib` (396 статьи / 628 оглавления), 355 `/buy/`,
  95 внешних, 1 голый слаг без `-lib` (`pozdravleniya-s-imeninami-valeriya`),
  ~11 относительных `show_item.php` - магазин шире префикса `/buy/`.
