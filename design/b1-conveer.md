# Переход к БД
Промышленный MDX-конвейер: четыре слоя
Любая зрелая MDX-платформа (доки Vercel, Astro-контент, Contentlayer-подобные системы) устроена одинаково:
1. ИСТОЧНИК      откуда берётся строка с MDX
                 (файл на диске / БД / CMS по API)
                          │
2. ПАРСИНГ МЕТЫ  gray-matter: строка → { data, content }
                 data → Zod → типизированный Article
                          │
3. КОМПИЛЯЦИЯ    MDX-компилятор + remark/rehype-плагины:
                 content → React-компонент
                          │
4. РЕНДЕР        компонент + реестр (mdx-components) + prose-слой
                 → HTML

Ключевая мысль: при переезде на БД меняется только слой 1. 

БД-эпоха
- Слой 3 конфигурируется в одном месте (next.config сейчас; при переходе на компиляцию-в-адаптере — в опциях компилятора там). Список плагинов — часть контракта контента, как словарь компонентов: новый плагин = новое обязательство.
- Кандидаты в плагины на будущее: remark-gfm (таблицы — появятся ли в корпусе, покажет B1), rehype-slug (id заголовков — понадобится для оглавлений B2). Дисциплина та же, что с <Epigraph>: по второму случаю, не впрок.
