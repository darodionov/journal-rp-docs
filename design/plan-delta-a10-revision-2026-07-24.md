## 1. Решения ревизии

1. **Политика ссылок chrome — трёхстадийная (strangler в навигации).**
   Каждая ссылка шапки/футера, чей раздел ещё не мигрирован, живёт в одной
   из стадий: (1) заглушка `href="#"` — сейчас; (2) внешняя ссылка на
   действующий легаси-сайт — как только владелец даст URL; (3) внутренний
   маршрут — когда раздел мигрирует (B2, арка C, вертикаль магазина).
   Касается: О нас, Контакты, Вход/Регистрация, Магазин книги, События,
   Паломничество. Политику записывает мини-ADR A10.
2. **Полка «Библиотека» — один блок, два размещения.** Десктоп (≥ lg 1024):
   карточки товаров в правом сайдбаре под баннером. 768/320 (< lg): тот же
   набор товаров — врезка внутри тела статьи (`Biblioteka_320_1/2`).
   Следствия: (а) пробел «полка-врезка desktop — макета нет» СНЯТ, отдельный
   макет не нужен; (б) возникает вопрос источника ids — см. раздел 4,
   вопрос В2 мини-ADR.
3. **Спека стилей тела статьи фиксируется сейчас** (раздел 3), вёрстка — по
   шагам A11/A12 строго по спеке. Код пишет владелец (правило 1 режима
   обучения); спека снимает «вспоминание решений», не учебную работу.
4. **Состав соцкнопок пересмотреть.** В макете 2016 года — FB / VK / Twitter.
   Редакционное решение о актуальном составе — до вёрстки блока в A11
   (техника не меняется: ссылки-шеры без JS).
5. **Хвосты вёрстки chrome получают адреса** (не были назначены в плане):
   логотип-ассет и полный футер → A11; бургер-иконка, кнопка-лупа, контент
   дровера → A12. Подробно — в правках шагов.

## 3. Спека стилей тела статьи (для A11/A12)

Токены — по `Tokens_Handoff.md` (срез 2026-07-10). Точные пиксельные
размеры сверяются с макетом при вёрстке; спека фиксирует токены, анатомию
и поведение. Контентная типографика живёт в prose-слое (ADR-0004 п. 3),
компоненты — поверх.

### 3.1. Каркас: content-grid статьи

- Грид контентной колонки с именованными линиями:
  `[full-start] … [wide-start] … [text-start] текстовая мера [text-end] … [wide-end] … [full-end]`.
- По умолчанию все дети — в `text`; изображения-breakout — в `wide`;
  hero — в `full` (вся контентная колонка, не под сайдбаром).
- Сайдбар — вторая колонка страничного грида: `--sidebar-w` (218px),
  зазор `--gutter`; страница ограничена `--page-max` (1280),
  выше — растут поля.
- Учебная тема A11: named grid lines + почему это лучше отрицательных
  маргинов (устойчивость к изменению меры).

### 3.2. Заголовочная зона

- h1: `--fs-h1`, `--lh-heading`, `--text-heading`, bold, по центру.
- Строка дат памяти (нов./ст. стиль): `--fs-small`, `--text-accent`,
  по центру, bold.
- Лейбл рубрики над заголовком: капс, `--tracking-label`, `--fs-tiny`,
  `--link-warm` (ссылка на рубрику — стадия по политике ссылок).

### 3.3. Изображения

- **Hero (горизонтальная обложка):** колонка `full`; соотношение — по
  макету; без скругления и тени (система плоская).
- **Вертикальная обложка:** колонка `text`, не растягивать; центр.
  Правило выбора: `height > width` из фронтматтера (обязательные
  width/height, схема A4 — это их названный сценарий).
- **Breakout-изображение:** колонка `wide`, выравнивание к левому краю
  `text`, выход вправо.
- **Подпись (обязательна для всех контентных изображений):** `figure` +
  `figcaption`; `--fs-small`, курсив, `--text-muted`, по центру,
  отступ `--space-2` сверху.
- Механизм в MDX: компонент `Figure` (или маппинг `img → figure` в
  mdx-components) — выбрать в A11; без подписи — ошибка контента,
  не молчаливый рендер.

### 3.4. Автор-блок

- Раскладка: две колонки — аватар-колонка | текст автора.
- Аватар: круглый (`border-radius: 9999px` — единственное разрешённое
  исключение из `--radius: 3px`), размер по макету (~64–80px).
- Имя: капс, `--tracking-label`, `--fs-tiny`, `--text-muted`, по центру
  под аватаром; роль — вторая строка, `--fs-tiny`, `--text-muted`.
- Авторов может быть несколько по ходу текста (аудит) — блок повторяемый.

### 3.5. Pull-quote (цитата-врезка)

- Анатомия: полоса-разделитель `--border-divider` сверху и снизу;
  орнаментальные кавычки « » `--text-accent` на полосах (открывающая
  сверху, закрывающая снизу), крупные.
- Текст: по центру, размер между body и h2 (базово 1rem/`--fs-h3`,
  сверить с макетом), `--text-body` или `--text-heading` — сверить;
  мера уже текстовой (внутренние поля `--space-8`+).
- Компонент существует с A5 — в A11 довести полосы/кавычки до макета.
- Механизм выделения текста: редакционный — автор дублирует/выносит
  фразу в компонент руками; автоматики нет (заметка B1).

### 3.6. Соцкнопки-шеры

- Ссылки-шеры без JS (`href` на share-URL сетей), под статьёй.
- Брендовые цвета сетей — допустимое исключение из палитры;
  зафиксировать свотчи на `/dev/tokens`.
- Состав — по решению ревизии п. 4 (макетный FB/VK/Twitter устарел).

### 3.7. Ряды под статьёй

- Лейбл секции («ДРУГИЕ МАТЕРИАЛЫ ПО ТЕМЕ», «СОБЫТИЯ»): капс,
  `--tracking-label`, `--fs-tiny`, `--text-muted`.
- «По теме»: 7 мини-карточек в ряд (desktop); карточка: фото, заголовок
  `--fs-small` `--text-heading`; ховер — `--state-hover-tint` /
  `--link-hover` на заголовке, `--transition-colors`.
- «События»: карточки с датой (`--text-accent`) и текстом.

### 3.8. Сайдбар (desktop ≥ lg)

- Блоки на `--surface-card`, граница `--border-divider` 1px,
  радиус `--radius`; без теней.
- Цитата дня: текст + атрибуция книги `--fs-small` `--text-muted`;
  кавычки `--text-accent`.
- Баннер: изображение-ссылка; источник — фикстурный модуль (не порт).
- Товарный блок «Библиотека» (BookShelf, desktop-размещение): строка
  товара — обложка мини, автор `--fs-tiny` `--text-muted`, название
  `--fs-small` `--text-heading`, цена `--price` bold, кнопка
  «В корзину» `--button-primary` / ховер `--button-primary-hover`,
  `--radius`, `--transition-colors`; иконки отзывов hairline.
- Лента событий: дата `--text-accent`, текст `--fs-small`.

### 3.9. Полка-врезка (< lg, из BookShelf)

- По `Biblioteka_320_1` (вертикальная карточка + «Показать больше») и
  `_2` (горизонтальная карусель — клиентское только скролл,
  CSS scroll-snap, без JS).
- Карточка: обложка, автор, название, видео-отзыв + N отзывов, цена
  `--price`, «В корзину» `--button-primary`.
- Мультиконтекстность товар-карточки (сайдбар/врезка/карусель) — через
  `@container` (Tokens_Handoff п. 5), не viewport-брейкпоинты.

## 4. Дополнение каркаса мини-ADR A10

К каркасу «Контекста» из ревизии добавить вопросы решения:

- **В1. Политика ссылок chrome** — три стадии (раздел 1, реш. 1);
  перечислить все затронутые ссылки и их текущую стадию.
- **В2. Где живут ids товаров статьи** — конфликт с дополнением реш. 2
  («MDX-компонент `<BookShelf ids={...}/>`»): при адаптивном размещении
  сайдбар (зона шаблона) не имеет доступа к телу MDX. Варианты:
  (а) фронтматтер `books: [...]` — шаблон рендерит сайдбар и врезку из
  одного источника; врезка < lg позиционируется шаблоном (место в потоке —
  решить: фикс. позиция vs MDX-маркер без ids); (б) ids в теле MDX —
  сайдбару нужен извлекатель из скомпилированного контента; (в) дубль в
  обоих местах — рассинхрон. Выбор обосновать; реш. 2 дополнения уточнить
  ссылкой на ADR.
- **В3. Судьба сквозняков**: Вход/Регистрация, Ctrl+Enter, текст-визитка
  магазина в футере, 8-800 — стадия/скрытие.
- **В4. Планка «Последствий»** (критерий качества ADR): явный абзац —
  что придётся сделать при подключении живого магазина и чего делать
  НЕ придётся.

## 5. Промпты Claude Design

Общая преамбула к каждому промпту: приложить Design Guide (standalone) /
Tokens_Handoff и референс-макеты статьи; работать строго на токенах.

### А. Лента рубрики + пагинация (пробелы №1–2, дедлайн — до B2)

> Спроектируй страницу «Лента рубрики журнала» для «Русскій Паломникъ»
> строго по приложенному дизайн-гайду (токены: палитра, PT Sans,
> радиус 3px, плоско, без теней). Референсы композиции — приложенные
> макеты статьи и главной; chrome (шапка/футер/правый сайдбар) — как в
> статье. Состав: хлебная крошка или лейбл раздела; заголовок рубрики
> (стиль h1 статьи); сетка карточек материала — использовать
> существующие карточки инвентаря (крупная: фото, лейбл рубрики
> терракотовым капсом, заголовок, анонс, дата); 12 карточек на страницу;
> внизу — пагинация (URL-паттерн `…/page/2/`): предыдущая/следующая +
> номера, активная страница — тёплый акцент, ховер — бирюза; состояния
> ссылок по токенам --state-*. Брейкпоинты: 1600 (двухколоночная с
> сайдбаром), 768 и 320 (одноколоночная, сайдбар вниз или скрыт — как
> в статье). Дореволюционная орфография в декоративных элементах —
> элемент бренда. Выход: три артборда (1600/768/320) + отдельный лист
> состояний пагинации.

### Б. Страница 404 (пробел №4, к A12)

> Спроектируй страницу 404 для «Русскій Паломникъ» по приложенному
> дизайн-гайду. Тон — спокойный, в духе журнала; допустима
> дореволюционная орфография («Страница не найдена / Страницы сей не
> обрѣтено» — предложи варианты). Состав: chrome как в статье (шапка +
> футер, без сайдбара); крупный код 404 или орнаментальный элемент в
> палитре (терракота/коричневый); одна строка объяснения (--text-muted);
> действия: ссылка на главную (primary-кнопка бирюзовая) и 2–3 ссылки
> на разделы (тёплые ссылки). Без иллюстративного стока — только
> типографика, палитра, орнаментальные кавычки-скобы как мотив.
> Брейкпоинты 1600/320. Выход: два артборда.

### В. Лист hover/focus-состояний (пробел №6, к A11)

> По приложенному дизайн-гайду собери один лист «Состояния
> интерактивных элементов» (для фиксации на /dev/tokens): холодная
> ссылка (default/hover/focus-visible), тёплая ссылка (то же),
> primary-кнопка (default/hover/focus/disabled), тёплая кнопка (то же),
> текстовое поле (default/focus/error/disabled), строка списка
> (default/hover/selected), карточка материала (default/hover),
> товарная строка сайдбара (default/hover). Использовать только токены
> состояний: --link-hover, --link-warm-hover, --button-*-hover,
> --focus-ring (холодное кольцо) / --focus-ring-warm,
> --state-hover-tint, --state-selected-bg, --disabled-*, --danger*.
> Переходы: --transition-colors (150ms). Никаких теней и масштабирований.
