# Карта легаси-сайта idrp.ru (справочник для миграции журнала)

Обследование: 2026-07-03..04. Источники:
- код в `legacy/` (симлинк на `/Users/dr/Code/ru.idrp/idrp.ru/rp`);
- дамп БД `/Users/dr/Code/ru.idrp/idrp.ru/DB/2018-11-17_02-10_db_idrp.sql`
  (16 ГБ, mysqldump, MySQL 5.6.34, снят 2018-11-17). Дамп старше кода
  (код правился до 2024), но структура журнальных таблиц в коде и дампе
  совпадает; для финального переноса контента понадобится свежий дамп.

## 1. Общая картина

- Плоский PHP-сайт без фреймворка: точки входа - отдельные `.php` в корне,
  общий шаблонизатор `TPL` (`_src/tools/TPL.php`), трехколоночный макет
  `_tpl.main.php`.
- БД: MySQL (mysqli), база `idrp`. Подключение захардкожено в
  `_src/XDB.class.php` (креды в коде - в карту не копируем).
- Кодировка ВСЕГО - windows-1251: php-файлы, htm-контент, default_charset
  в `.htaccess`, все журнальные таблицы (`DEFAULT CHARSET=cp1251`
  подтверждено дампом). Миграция потребует конвертации в UTF-8.
- Роутинг размазан по двум местам: rewrite-правила в `.htaccess` и
  php-роутер-редиректор `buy/noindex/link_wrapperx.php`.
- Журнальная часть - ДВЕ разные подсистемы разных поколений:
  1. "Старый журнал" - контент в htm-файлах на диске, метаданные в таблицах
     `articles` / `articles_column`. URL вида `/article/?article=4`.
  2. "Новая библиотека" (articlex) - контент целиком в БД, таблица `articlex`.
     URL вида `/content/article/<slug>-lib<id>/`.
- Рядом два брошенных эксперимента с фреймворками: `magazine/` (пустой
  Symfony-скелет) и `main/` (заглушка на Silex). Контента и логики в них нет.

## 3. Схема БД (точная, из дампа 2018-11-17)

### 3.1 articlex - статьи "новой библиотеки" (основной объект миграции)

`ENGINE=InnoDB, CHARSET=cp1251, COMMENT='Статьи'`. FULLTEXT-индекс по body.
В дампе **1662 строки** (AUTO_INCREMENT=1666). Суммарный объем body ~23 МБ,
средняя статья ~14 КБ HTML, максимальная ~755 КБ. Закрытых (is_close=1) - 13,
внешних (isext=1) - 4, без slug (url пустой) - 22, last_date до 2018-04-19.

### 3.2 dic / dic_data - универсальный справочник

- `dic(n PK, up, name, ...)` - список словарей (~120 штук, почти все
  магазинные).
- `dic_data(n, up, upx, name, name1, name2)` - значения; PK (n, up),
  `up` -> dic.n.

Журнальные словари: 16 тема цитаты (129), 17 тип статьи (27), 18 автор
цитаты (55), 20 раздел ЖС (5), 21/37 месяцы им./род. падеж (13), 22
персоналии ЖС (1184), 29 муж. имена (52), 32 жен. имена (39), 36 тип
дизайна (2).

### 3.3 cal - календарные даты

`cal(id PK, dt_day, dt_month, obj varchar(32), obj_id)` - универсальная
привязка объекта к дате; для статей obj='ARTICLEX', obj_id -> articlex.id.
В дампе 1054 строки. Заполняется хранимой процедурой
`dtnameday_add(day, month, obj, obj_id)`. Используется для именин (type 14/15).

### 3.4 Старый журнал: articles, articles_column

- `articles(num PK smallint, date, magazine_num tinyint, title varchar(90),
  column -> articles_column.num, is_open)` - 39 статей (AUTO_INCREMENT=40),
  2005-2008 гг., дореволюционная орфография в заголовках. Контента в БД НЕТ -
  body лежит в `pages/article/all/<num>/index.htm`.
- `articles_column(num PK, column varchar)` - 12 рубрик: Американскiй
  Патерикъ, Валаамская Патрологiя, Иноческая Л(ять)ра, Русскiй Мартирологiй,
  Вселенскiе Святые, Современный Патерикъ, Искусство Святой Руси, Исихазмъ,
  Афонскiй Патерикъ, Передовица журнала, Книги, Новый россiйскiй мартирологiй.

### 3.5 Прочее, задевающее журнал

- `articlex_lev(id_article, code_no, lvl)` - похожесть статья<->товар,
  генерируется скриптом `buy/mv_lvl.php` для блока рекомендаций.
- Магазин (вне миграции журнала, но живет в тех же шаблонах): products,
  products_tag, products_tag_link, prubric, pgroupmain, pgroupsecond, const.
  "Последний номер журнала" на главной - это товар из products (prubric
  prid=2, sid=1).

## 4. Маршруты и URL журнальной части

### 4.1 Канонический URL статьи (articlex)

    /content/article/<slug>-lib<id>/   ->   article.php?rd=1&id=<id>

Правило из `.htaccess`:

    RewriteRule ^content/article/[A-Za-z0-9_\-]*-lib([0-9]+)?/$ /article.php?rd=1&id=$1 [L]

ВАЖНО для миграции: роутер захватывает только `<id>`, slug игнорируется -
любой slug с правильным id отдает статью (дубликаты URL возможны). Slug
берется из articlex.url только при ГЕНЕРАЦИИ ссылок
(`/content/article/{url}-lib{id}/` - шаблон разбросан по коду). 22 статьи
в дампе вообще без slug.

Цепочки нормализации (все 301):

    /<slug>-lib<id>              -> /content/article/<slug>-lib<id>/
    /<slug>-lib<id>/             -> /content/article/<slug>-lib<id>/
    /content/article/...-lib<id> -> .../-lib<id>/  (добавление слеша)
    /article.php?id=<id>         -> link_wrapperx -> /content/article/<url>-lib<id>/
                                    (url достается из БД по id)

### 4.2 Старый файловый журнал

    /article/                     - список рубрик (rewrite -> link_wrapperx?t=old_article
                                    -> include pages/article/article.php)
    /article/?column=<M>          - статьи рубрики M (12 рубрик, п.3.4)
    /article/?article=<N>         - статья N (контент из pages/article/all/N/index.htm)
    /pages/article/article.php?.. -> 301 -> /article/?..

Пагинации в привычном виде нет: внутри статьи - навигация "пред/след" по
num (+1/-1) и список статей рубрики без текущей. Метаданные - из таблиц
articles/articles_column, title/keywords/description - из meta-тегов htm-файла.

### 4.3 Страница журнала и главная

    /journal   -> pages/article/history.php (301 обратно с history.php на /journal)
                  контент - файл pages/article/all/0/index.htm
    /          -> index.php: блок дня (articlex id=1665), "колесо" календаря из
                  pages/article/days/MMDD.htm, "Читальный зал" - 3 случайные
                  articlex с on_main_page=1, ссылки на старый журнал

### 4.4 Разделы, "категории", теги

- Категорий как отдельной сущности у articlex НЕТ. Разделы - это сами статьи
  (type=7 и др.): страница-оглавление рендерит список детей запросом по
  `type`/`src_saints` (block_list=1) плюс захардкоженные в article.php ссылки
  на 12 месячных указателей житий (type=22, `zhitiya-yanvar-lib1325`...).
- Именины: списки имен генерируются из articlex type=14/15 + словари имен
  (dic 29/32), даты - из таблицы cal. URL - обычные статейные
  (`imeniny-<imya>-lib<id>/`).
- Тегов у журнала нет. `/tags.php` и `-t<id>` URL - это теги МАГАЗИНА
  (products_tag), к миграции журнала не относятся.

### 4.5 Точечные 301 из .htaccess (важно для карты редиректов)

- Пачка сервисных статей уведена со статейных URL на магазинные:
  `kontakti-lib1600`, `pravila-obmena-lib1549`, `o-registracii-lib1539`,
  `kak-sdelat-zakaz-lib1579`, `statusi-lib1541`, `sposobi-oplati-lib1561`,
  `sposobi-dostavki-lib1538`, `skidki-lib1599`, `help-lib1594` - все ведут на
  `/buy/kontakti/`, `/buy/help/...`, где рендерятся тем же article.php.
- `/journal` <-> history.php, `/article` -> `/article/` и пр. (см. выше).
- Sitemap не найден, в robots.txt директивы Sitemap нет.

## 5. Где лежит контент (для экспорта в MDX)

1. **articlex.body** - готовый HTML в БД (cp1251): инлайн-стили, таблицы,
   картинки. 1662 статьи, ~23 МБ HTML, средняя ~14 КБ, максимум ~755 КБ.
   Ссылки между статьями - обычные `<a href="/content/article/...">`.
   В полях lnk/nm разметка `[[текст]]` - код оборачивает ее в `<a>`.
   Это основной корпус для миграции; ядро - жития (1199 статей).
2. **pages/article/all/<N>/index.htm** - старый журнал: 43 папки
   (N = -10, 0..41; в БД 39 записей), в каждой index.htm + картинки рядом
   (image001.jpg...). В htm - meta keywords/description. При выводе разрешен
   белый список тегов (fgetss + ALLOW_TAGS: a, b, i, div, span, img, h1-h3,
   br, p, cite, blockquote), пути картинок переписываются на
   /pages/article/all/N/. N=0 - "история журнала" (страница /journal).
3. **pages/article/days/MMDD.htm** - заметки к датам (имя файла = месяц+день),
   показываются на главной "колесом" ближайших дат.
4. Картинки житий дополнительно в `htm/zhitiya-pic/`.

## 6. Открытые вопросы

1. Дамп датирован 2018-11-17, код правился до 2024: перед финальным
   переносом контента нужен СВЕЖИЙ дамп продовой БД (минимум articlex, dic,
   dic_data, cal). Структура, судя по коду, не менялась; строк, вероятно,
   немного больше (в дампе id до 1665, код ссылается на id=1665 включительно).
2. Sitemap на сайте отсутствует - карту редиректов строить из .htaccess +
   этой карты + (в идеале) данных Вебмастера/Search Console.
3. 22 статьи без slug (url пустой) - при миграции им нужно сгенерировать
   slug и решить, какие URL у них были реально проиндексированы.
4. Статья id=1665 (блок дня на главной) - служебная вставка, не контент;
   учесть при отборе корпуса (как и type=8 Служебные, 19 Фрагменты,
   9 Рекламные лоты).
