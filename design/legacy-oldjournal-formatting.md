# Словарь форматирования старого журнала (вход для A5 и конвейера MDX)

Дата: 2026-07-21. Корпус: 39 выпусков старого журнала
`legacy/pages/article/all/<1..39>/index.htm` (+ служебные `!.ogl`), cp1251.
Живой рендер: `https://idrp.ru/article/?article=<num>`. Скрипт аудита:
`journal-ai/scripts/oldjournal_format_audit.py`. Рядом: `legacy-dump-checks.md`
(п. 7 - состав папок), `extracted/article-4-oldjournal` (эталонный образец).

## Метод

- Все 39 `index.htm` прогнаны через HTML-парсер: счетчики тегов, классов,
  inline-стилей, презентационных атрибутов; отдельно `!.ogl` (35 файлов).
- Для каждого частого паттерна отсмотрены живые вхождения в контексте -
  классификация ниже семантическая, не только синтаксическая.
- Классы статей (`picDiv`, `picbutton`, `cite`, `snoska`, `medium`, `letter`,
  `big`) НЕ определены ни в одном CSS репозитория - либо стили утеряны, либо
  рендер жил на дефолтах браузера. Семантику восстанавливаем по употреблению.

## Структура файла выпуска (не тело, а обвязка)

- `index.htm` - НЕ полная страница, а фрагмент: 2 `<meta>` (keywords,
  description) + тело. Рендер (`pages/article/article.php`) читает meta через
  `get_meta_tags`, заголовок и рубрику берет из БД `articles` и добавляет сам.
- `!.ogl` - шапка выпуска: `fieldset/legend` с номером бумажного журнала
  («Русскiй Паломникъ» №N-ГГГГ), блок заголовков (h1-h3, копирайт), у 27 файлов
  оглавление `ol/li + a.ogl_navi` со ссылками на постраничный рендер
  `jurnal.php?name=...&page=N` (мертвый механизм пагинации).
- Заголовки БД и `!.ogl` - в дореформенной орфографии; рендер переводил их в
  современную (`pg_main::ConvertToNewTextStyle`). В теле перевода НЕ было.
- Склейки: файлы 7, 11, 31, 34 содержат по 4 `<meta>` (двойные статьи),
  файлы 24-27, 30, 33, 34 - повторные `<title>` посреди тела. При конвертации
  резать вручную.
- В новой схеме вся обвязка уходит в frontmatter: заголовок (совр. + дореф.),
  выпуск, рубрика (из `articles_column`), дата, оглавление глав.

## Словарь элементов тела

Колонки: вхождений / в скольких файлах из 39.

| `<h2>` | 80 / 14 | подзаголовки, названия стихотворений, номера писем | `###` |

### B. Семантические блоки - кандидаты в MDX-компоненты

Пока размечаем Markdown-примитивами (правая колонка), компонент заводим, когда
дойдет очередь по покрытию.

**B1. Эпиграф с атрибуцией** - `div.cite` (23 / 13): внутри `<cite>` текст +
`<blockquote>` как строка источника («(Іоан. 14,12)», «Преп. Серафимъ»).
Внимание: `blockquote` здесь - НЕ цитата, а подпись под ней.
Сейчас: blockquote + строка курсивом. Будущее: `<Epigraph author="...">`.

Конвертация: весь блок - один blockquote, атрибуция - последний абзац внутри
него, курсивом и с тире; если текст эпиграфа стихотворный (`<br>` внутри
`cite`), строки заканчиваем `\`:

```mdx
> «Истинно, истинно говорю вамъ: вѣрующій въ Меня, дѣла, которыя
> творю Я, и онъ сотворитъ, и больше сихъ сотворитъ ...»
>
> *- (Іоан. 14, 12)*
```

Потом это станет `<Epigraph author="(Іоан. 14, 12)">текст</Epigraph>` -
конвертер найдет такие blockquote по последнему курсивному абзацу с тире.

**B2. Лид / вводка** - одиночный `<cite>` (76 / 26, из них ~55 вне `div.cite`):
курсивная вводка в начале статьи или главы, от редакции.
Сейчас: абзац курсивом. Будущее: `<Lead>` или проп в шаблоне.

Конвертация: обычный абзац целиком курсивом, сразу после заголовка. НЕ
blockquote - иначе не отличить от эпиграфа B1:

```mdx
## Предисловіе

*Передъ самымъ прославленіемъ Преподобнаго Серафима, въ 1903 году,
Сергѣемъ Нилусомъ были обнаружены записи друга и почитателя святаго...*
```

Потом: `<Lead>...</Lead>`; признак для конвертера - полностью курсивный
первый абзац после заголовка.

**B3. Подпись / атрибуция после текста** - два равнозначных приема:
голый `<blockquote>` после стихов и писем (~57 / 13: «Петроградъ. Февраль
1917 г.», «Эри, Пенсильвания») и `<p align="right"><i>` (12+7 вхождений:
«Сергiъй Нилусъ», «Шанхай, 1948 г.»). Одна семантика - автор/место/дата.
Сейчас: абзац курсивом. Будущее: `<Attribution>` (или проп `<Epigraph>`/письма).

Конвертация: отдельный абзац курсивом сразу после текста, к которому
относится; несколько строк (имя + место + дата) - через `\`. Выравнивание
вправо не имитировать, это дело будущего компонента:

```mdx
Не имѣемъ здѣ пребывающаго града, но грядущаго взыскуемъ.

*Сергій Нилусъ\
19 Мая 1903 г.*
```

Потом: `<Attribution>Сергій Нилусъ, 19 Мая 1903 г.</Attribution>`; признак
для конвертера - короткий полностью курсивный абзац после стихов/письма.

**B4. Иллюстрация с подписью** - `div.picDiv` (217 / 38, ширина inline-стилем
135-500px) + `img` + `div.picbutton` (227 / 36) с подписью. Подпись есть
практически у каждой редакционной картинки - это норма корпуса, не исключение.
Один раз `span.picDiv` (файл 39, без подписи), один раз обертка `<center>`.
Сейчас: картинка + абзац-подпись. Будущее: `<Figure caption="...">`;
width из inline-стиля - в подсказку размера, alt писать заново (в легаси 14/232).

Конвертация: этот блок настолько частый, что примитивами его лучше не
размечать - `<Figure>` заводим первым и конвертируем сразу в него. Подпись
из `picbutton` идет в `caption`, alt пишем заново по смыслу (текст подписи -
приемлемый черновик alt), width берем из inline-стиля `picDiv`:

```mdx
<Figure
  src="./image001.jpg"
  alt="Валаамскій портретъ преподобнаго Серафима"
  width={300}
  caption="Валаамскiй портретъ Прпд. Серафима"
/>
```

Если на момент конвертации `<Figure>` еще нет - временно картинка плюс
абзац-подпись курсивом следующей строкой:

```mdx
![Валаамскій портретъ преподобнаго Серафима](./image001.jpg)
*Валаамскiй портретъ Прпд. Серафима*
```

**B5. Сноски** - только файл 10: маркер `span.snoska > a href="#"` (3 шт.),
внизу `<hr>` + `<a name="snoska">` + `<ol>` с текстами. Якоря мертвые (href="#").
Сейчас/будущее: footnotes `[^1]` (remark-gfm) - компонент не нужен.

Конвертация: маркер в тексте - `[^n]`, тексты сносок - в конец файла;
легасийные `<hr>`, `<a name>` и нумерованный `<ol>` выбрасываем, нумерацию
и блок внизу страницы рисует remark-gfm сам:

```mdx
Это был иеромонах Иоанн (Максимович)[^3], русский по происхождению.

[^3]: Будущий архиепископ Шанхайский и Сан-Францисский.
```

**B6. Стихи** - два приема: `blockquote.medium` (113 / 3, файл 3 в основном) -
чередование строк `blockquote.medium` и `<p>` дает лесенку строфы; и просто
`<p>` на строку либо `<br>` внутри абзаца/цитаты (основная масса 409 `<br>` /
22 файлов - стихи, адреса, разрывы в подписях). В файле 34 - акафист:
центрированные строфы с `<br>`.
Сейчас: абзацы со строками через два пробела/`<br>`. Будущее: `<Verse>`
(лесенку легаси не воспроизводим - это артефакт вёрстки).

Конвертация: строфа = абзац, строка стиха = строка с `\` на конце (жесткий
перенос; два пробела не использовать - их едят форматтеры). Лесенку
`blockquote.medium` и центрирование акафиста НЕ переносим - все строки с
левого края, отступы отдаст будущий `<Verse>`:

```mdx
Кресты высокихъ колоколенъ\
Еще сiяютъ здѣсь и тамъ,\
Какъ будто солнца замедленье\
На каждомъ куполѣ златомъ.

Напомнить хочетъ намъ о Томъ...
```

Название стихотворения - `###`, подпись с датой после - по B3.

**B7. Письмо-цитата** - `p.letter` (1 / 1), гигантские `<i>` на все письмо,
блоки писем читателей в файле 10 (h3-обращение + текст + blockquote-подпись).
Сейчас: blockquote. Будущее: `<Letter>` - только если решим выделять письма
визуально; покрытие маленькое.

Конвертация: все письмо - один blockquote: обращение первым абзацем, текст
обычными абзацами (курсив гигантских `<i>` снимаем - это оформление, не
семантика), подпись - последним абзацем курсивом (как B3, но внутри цитаты):

```mdx
> Дорогие отцы!
>
> Мы прочли буклет, вышедший в Калифорнии, посвященный владыке Иоанну...
>
> *05 октября 1971 года, Австралия*
```

**B8. Разделитель «* * *»** - `<p>* * *</p>` (6 / 1, файл 3, между
стихотворениями). Сейчас: `---`. Будущее: вариант `<hr>` со звездочками -
чисто CSS, компонент не нужен.

Конвертация: просто `---` (пустая строка до и после, иначе Markdown примет
за setext-заголовок). Звездочки не сохраняем - их вернет CSS на `<hr>`:

```mdx
...И возсiяетъ крестъ высокъ.

---

Мнъ дорогъ часъ, когда царицей властной...
```

### D. Дореформенная орфография - сквозная особенность корпуса

- 35 / 39 тел содержат ять/фиту/ижицу и пр. - числовыми сущностями
  (`&#1122;` Ѣ, `&#1123;` ѣ, `&#1138;` Ѳ, `&#1139;` ѳ, `&#1141;` ѵ) вперемешку
  с i десятеричным и ъ обычным текстом. Файл 10 и часть поздних - современная
  орфография.
- Ловушка: встречаются сущности БЕЗ точки с запятой (`&#1123` в файле 4) -
  наивный декодер их пропустит, браузерный - съедает следующий символ.
  Декодировать в юникод (Ѣѣ...) на входе конвейера, хранить как текст UTF-8.
- Заголовки существуют в двух орфографиях (тело - дореф., рендер БД - совр.);
  в frontmatter нести обе, отображение - решение дизайна, не конвейера.

## Очередность компонентов (по покрытию корпуса)

1. `<Figure>` - 38/39 файлов, 217 блоков. Без него не собирается ни один выпуск.
2. `<Epigraph>` (+ атрибуция) - эпиграфы в 13 файлах, лиды в 26, подписи в ~13:
   одно семейство «курсивный блок с атрибуцией», закрывает B1-B3.
3. Сноски remark-gfm - 1 файл, но механика нужна и для articlex.
4. `<Verse>` - 3 файла со стихами + акафист; до тех пор - обычные абзацы.
5. `<Letter>` - под вопросом, можно навсегда оставить blockquote.

Для шага A5 достаточно: prose-слой + blockquote/курсив по словарю выше, а в
блокнот шага - «в корпусе есть эпиграфы (B1), лиды (B2), подписи (B3), подписи
картинок (B4) - размечаем примитивами, компоненты по очередности выше».
