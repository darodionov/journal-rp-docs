# Аудит вёрстки des-2016 для переноса в Next.js

Дата: 2026-07-07. Объект: `../legacy/des-2016` (статический HTML-кит журнала).
Скоуп зафиксирован с заказчиком: только des-2016; магазин (des-dev/di/build) - отдельным проходом;
конфигуратора рамок в legacy не существует. Режим read-only, исходники не менялись.

---

## 1. Резюме

**Вердикт: частичный реюз.** Кит пригоден как визуальный эталон и источник дизайн-токенов,
но не как источник кода. Разметку и стили переверстываем на новый стек; переносим сетку
страниц (3-8-3 колонки), типографику статьи и извлеченные токены. Ничего в вёрстке не
блокирует SSG - серверных вставок нет, интерактив изолируется в острова.

| # | Блок | Оценка 1-5 |
|---|------|-----------|
| 1 | Семантика и структура HTML | 2 |
| 2 | SEO-готовность | 1 |
| 3 | Доступность (a11y) | 2 |
| 4 | CSS-архитектура | 2 |
| 5 | Адаптивность | 3 |
| 6 | Производительность фронта | 2 |
| 7 | JS-слой | 2 |

**Три главных вывода:**

1. **SEO-слоя в вёрстке нет вообще.** Пустой meta description, ноль OG/canonical/schema.org,
   ноль заголовков h1-h6 на всех трех журнальных шаблонах. Вся SEO-обвязка строится в
   Next.js metadata API с нуля - из кита переносить нечего. Это одновременно и главный риск
   (перенос "как есть" не даст Lighthouse SEO 95), и свобода: нет legacy-обвязки, с которой
   надо сохранять совместимость.

2. **Кит внутренне раздвоен.** Журнальные страницы и страницы именин сидят на двух
   параллельных CSS-стеках (`general-main.css`+`general-media.css` против `main.css`+`media.css`,
   88 из 164 селекторов общие) с двумя разными вариантами шапки. Переносить нечего "как есть" -
   сначала пришлось бы выбирать, какой из двух вариантов правильный.

3. **Токены извлекаются, но с дрейфом.** Палитра сводится к 4 смысловым цветам
   (коричневый, бирюзовый, терракотовый, серый), но бирюзовый существует в 5 вариантах,
   серый - в 7. Шкалы отступов нет (px-значения 3,4,5,6,7,8,10,12,13,15,16,20,24,40),
   rem не используется ни разу (1739 px против 0 rem). Черновик токенов - в разделе 5.

**Природа вёрстки:** статический HTML-кит от верстальщика. PHP/SSI-вставок ноль, серверной
логики нет. Живой сайт (view/, htm/, main/, pages/) на ассеты des-2016 не ссылается - это
эталон дизайна, а не рабочие шаблоны. Границы данных в разметке не размечены: даты, имена,
цены захардкожены (например "24 января 2016" в index-journal.html:33).

**Методология:** отсутствует. Смесь kebab-case и подчеркиваний (`section-item_h3`, `buy_btn`),
презентационные классы (`brown`, `pad`, `last` - index-journal.html:109,32,117),
FontAwesome-классы без самого FontAwesome в проекте.

**Два CSS-стека.** Журнальные страницы подключают normalize + fonts + general-main +
general-media + menu-style + flurid + owl (3 файла). Страницы именин - normalize + main +
media + fonts + menu-style + datepicker + owl. Стеки дублируют друг друга: 88 из 164
селекторов general-main.css присутствуют и в main.css (54%).

## 3. Качество по блокам

### 3.1 Семантика и структура HTML - 2/5

- Div-soup: на журнальных шаблонах нет ни одного `header`/`main`/`footer`/`article`/`section`.
  Единственный семантический тег - `nav.menu` (index-journal.html:50). Лендмарки сделаны
  через ARIA-роли на div: `role="banner"` (:43), `role="main"` (:104), `role="contentinfo"` (:801).
- **Заголовков нет.** На index-journal.html, article-01.html, rubrika.html - 0 тегов h1-h6.
  Заголовки имитированы div-ами: `div.news-title` (index-journal.html:201),
  `div.section-item_h2` (:245), заголовок статьи - `div.news-title > p` (article-01.html:137).
  На страницах именин h2/h5 с пропуском уровней и без h1 (birthday.html:219,222).
  h1 есть только на 404.html:56.
- Систематически битые списки: `<li>...</a><li>` вместо `</li>` (index-journal.html:111-117,
  article-01.html:121-128) - 102 ошибки no-implicit-close по валидатору.
- `<html lang="">` - пустой lang в стандартной ветке (все шаблоны, строка 5); lang="ru"
  прописан только в IE-ветках условных комментариев.
- `</hr>` (article-01.html:141,152,154,421) - 60 ошибок void-content; `<figure>` внутри `<p>`
  (article-01.html:411-415) - 6 ошибок element-permitted-parent; незакрытые `<p>` в карточках
  каруселей (article-01.html:218, index-journal.html:291).
- `<form method="LINK">` - несуществующий метод (index-journal.html:58).
- Валидатор (html-validate, recommended): **1968 ошибок всего**, из них 937 trailing
  whitespace и 110 условных комментариев (шум эпохи), **779 содержательных**: 164
  no-implicit-button-type, 102 no-implicit-close, 60 void-content, 16 form-dup-name,
  8 no-dup-id (duplicate id="form", birthday-alphabet-A.html:389), 1 close-order
  (лишний `</p>`, article-01.html:151).
- Позитив: в теле статьи есть `figure`/`figcaption` для врезок с подписями
  (article-01.html:145-148, 401-404) - структура статьи осмысленнее остального кита.

**Влияние на миграцию:** прямой перенос разметки в JSX невозможен без починки (незакрытые
теги JSX не скомпилирует); иерархию заголовков и лендмарки придется проектировать заново -
это делается бесплатно при переверстке.

### 3.2 SEO-готовность - 1/5

- `<title>` есть на всех шаблонах ("Русский паломник &raquo; Журнал", index-journal.html:9).
  **Это единственный элемент SEO-обвязки во всем ките.**
- `meta name="description" content=""` - пустой на всех 12 шаблонах (index-journal.html:10).
- Open Graph: 0. Canonical: 0. Schema.org (Article, Product, BreadcrumbList): 0.
- Заголовков h1 нет ни на одном контентном шаблоне (см. 3.1).
- alt у изображений: **22 из 257 img (8.6%)**. article-01.html: 4 из 43; index-journal.html:
  1 из 33 (и тот alt="Logotype" на логотипе). Из содержательных alt есть только на врезках,
  и те неверные: alt="Елена" на фото с подписью "Отец Дмитрий" (article-01.html:146-147).
- Тексты ссылок: карточки-тизеры обернуты в `<a href="#">` без текста вокруг картинок
  (index-journal.html:198-199); "видео отзыв"/"4 отзыва" - осмысленно, но ведут на "#".
- robots.txt в ките: `Disallow:` пустой (эталонный, не переносится).

**Влияние на миграцию:** 100% SEO-слоя (metadata API, OG, canonical, JSON-LD Article/
BreadcrumbList, sitemap) пишется с нуля в Next.js. В ките нет ни одного паттерна, который
надо было бы воспроизводить. Обязательный alt стоит зашить в Zod-схему фронтматтера MDX.

### 3.3 Доступность - 2/5

- Формы: `label` без `for` - связаны 16 из 41 (39%); в формах логина/подписки label вообще
  не привязаны (index-journal.html:63-66, 146-147). Инпуты без `name`
  (index-journal.html:64,66). `autocomplete` - 0 вхождений на весь кит (11 ошибок
  autocomplete-password по валидатору). Состояний ошибок в вёрстке нет вообще.
- ARIA: **0 aria-атрибутов** на весь кит. Роли есть (banner/main/navigation/search/
  contentinfo), из них 30 избыточных (`role="form"` на `<form>`). Выпадающие меню и
  мобильное меню - без aria-expanded/aria-haspopup.
- Клавиатура: кнопка мобильного меню - `div.material-menu-button` (index-journal.html:49),
  пункт "Вход/Регистрация" - `div.link.link-show` (:56): div-ы, с клавиатуры недоступны.
- Focus: `outline:0/none` в 10+ местах (general-main.css:284,311,315,363,752,756;
  main.css:827,831,867,954). Кастомных :focus-стилей меньше, чем подавлений с запасом
  (12 в main.css, 8 в general-main.css), часть элементов остается без видимого фокуса.
- tabindex с положительными значениями (tabindex="5" на "Забыли пароль?",
  index-journal.html:65) - ломает естественный порядок обхода.

**Влияние на миграцию:** формы и меню переверстываются в любом случае (см. 3.7);
доступность закладывается в новые компоненты, из кита не переносится ничего.

### 3.4 CSS-архитектура - 2/5

- Методологии нет, нейминг неконсистентен (см. раздел 2).
- **Специфичность - здоровая** (редкий плюс): максимум (2,0,1) - `#searchForm input#s`
  (general-media.css), медиана (0,1,1), id-селекторов 54 из 1768. Каскадных войн нет.
- `!important`: в своих файлах по 6 штук (main.css:1085-1176, general-main.css:948-1002) -
  и все в print-стилях из HTML5 Boilerplate, то есть законные. В вендорном foundation.css - 25,
  но файл мертвый.
- Мертвый код: PurgeCSS по всем шаблонам+JS отбрасывает ~5-6% (general-main.css: 21 селектор,
  main.css: 20). Внутри кита мертвечины мало. Реальная проблема - **межстековое дублирование**:
  88 общих селекторов между main.css и general-main.css, то есть шапка/футер/общие блоки
  описаны дважды и уже разъехались. Плюс целиком мертвые файлы: foundation.css (391 строка),
  jquery.formstyler.css, search.js, normalize.min.css и datepicker.min.css (0 строк - пустые).
- z-index: 9999 (x15), 99 (x13), 10, 9, 1 - магические плато без системы
  (general-main.css:181, main.css:240).
- `css/dist/flurid.min.css` **синтаксически битый**: незакрытый блок (postcss падает на
  строке 182); в конец минифицированного вендорного файла дописаны свои стили блоков
  (.block_0 и т.д.). Работает только благодаря прощающему парсеру браузера.
- Дизайн-токены: палитра - 51 уникальный цвет, сводимых к 4 смысловым группам с дрейфом:
  бирюзовый в 5 вариантах (#8bc8cf x55, #65c6cd x25, #8cc8d0 x13, #67c9d0 x6, #78adb2 x6),
  серые поверхности в 7 (#ebebeb x92, #e9e9e9 x23, #dddddd x15, #f4f4f4 x19, #f2f2f2 x9,
  #f6f6f6 x6, #eee x6), терракота в 3 (#dca28c x23, #c09983 x23, #daa384 x6), коричневый
  стабилен (#482c17 x53 + темный #411f0d x5). Типографика: PT Sans через 3 отдельных
  font-family ('ptsans'/'ptsansbold'/'ptsansitalic' - антипаттерн "вес через семейство"),
  размеры 12/13/14/16/18/20px (+80px на 404), line-height почти не задан (5 вхождений).
  Отступы: шкалы нет (см. резюме). Радиусы: 3px (x224 свои), 4px (вендор), 50%, 1000px (pill).
  Тени: две реальные (0 0 10px 5px rgba(221,221,221,1) x7; -15px 15px 15px -15px rgba(0,0,0,.2)).
  **Вердикт: система с сильным дрейфом - извлекается, но требует нормализации** (раздел 5).

**Влияние на миграцию:** тащить CSS-файлы в новый стек нельзя (двойной стек, битый вендор,
px-хардкод), но простая специфичность означает, что визуал легко воспроизводится
утилитами/токенами без распутывания каскада.

### 3.5 Адаптивность - 3/5

- Подход: desktop-first с диапазонными max/min-width запросами; сетка - float-грид flurid
  (клоны .column c width_N/16) + клирфиксы; flex/grid не используются.
- Брейкпоинты между стеками не совпадают: media.css - 7 блоков @media (320, 321+,
  480-950, 768-950, 951-1223, 1224-1280, 1281+), general-media.css - 6 (те же, но
  951-1280 одним куском). Плюс device-width-запросы (min-device-width:320 and
  max-device-width:480) и IE-хак `@media \0screen`.
- Единицы: **1739 px, 0 rem**, 35 em, 239 % в своих CSS. Фиксированные height в px - 72 шт.
- Отдельный антипаттерн: на десктопе страница **перезагружается при ресайзе окна** -
  `$(window).resize(... location.reload())` (index-journal.html:838-842) - адаптив между
  брейкпоинтами фактически не живой, а по-страничный.

**Влияние на миграцию:** брейкпоинты нормализуются в 4 точки без потери дизайна (см. 5);
сетка 3-8-3 переносится на CSS Grid одной строкой; px-значения конвертируются в токены
при переверстке. Средний балл - потому что покрытие диапазонов реально полное, дизайн
адаптируется на всех ширинах.

### 3.6 Производительность фронта - 2/5

Расчет для журнальной страницы (index-journal.html), gzip:

- CSS: ~21.5 КБ gzip / 175 КБ raw (normalize 2.7 + fonts 0.2 + general-main 4.4 +
  general-media 3.4 + menu-style 0.4 + flurid 4.3 + owl 1.1 + owl.theme 0.5 + animate 4.4).
  Из них animate.css - 72 КБ raw ради единственного эффекта fadeOut в карусели.
  9 render-blocking CSS-файлов в head.
- JS: ~57 КБ gzip своих + вендора (jquery 33.4 + modernizr 8.2 + plugins 0.9 +
  materialmenu 3.6 + owl 10.5) **плюс dojo.js 1.11.2 с CDN, который не используется вообще**:
  подключен вместо jQuery CDN (index-journal.html:823), строкой ниже фолбэк
  `window.jQuery || document.write(...)` всегда срабатывает и грузит локальный jQuery.
  Итого две библиотеки, из которых работает одна.
- Страницы именин: jQuery грузится с **http://** (mixed content, birthday.html:909)
  с фолбэком на неминифицированный jquery-1.11.3.js (278 КБ raw); сверху datepicker 9.4 +
  formstyler 5.3 + jquery.color 1.5 гzip.
- Изображения: только jpg/png, WebP/AVIF нет; srcset/sizes/loading= - 0 вхождений на кит;
  news-фото до 300 КБ (img/news/12.jpg, 1000px ширины) вставляются без размеров.
- Шрифты: 3.3 МБ - PT Sans в 5 форматах включая мертвые eot/svg; font-display не задан
  (fonts.css); в fonts.css битая ссылка на несуществующий originalptsansitalic.ttf
  (fonts.css:27). Лицензий в проекте нет (PT Sans - OFL, проблемы нет, но файлы лицензии
  отсутствуют).

**Влияние на миграцию:** ничего из этого не переносится: next/font + next/image + выброс
jQuery-стека решают все пункты автоматически. Цифры выше - baseline для сравнения "до/после".

### 3.7 JS-слой - 2/5

Весь интерактив - jQuery-плагины 2014-2015 годов:

| Функция | Реализация | Замена в новом стеке |
|---------|-----------|----------------------|
| Мобильное меню | materialmenu.jquery.js, инициализация `$('.material-menu nav > div')` | клиентский Header-остров |
| Карусели книг (2 вида) | owl.carousel + animate.css | embla/keen-slider или CSS scroll-snap |
| Календарь именин | datepicker.js (air-datepicker) + jquery.color | react-day-picker в острове |
| Стилизация форм | jquery.formstyler на все input/select (birthday.html:921-927) | нативные стили / shadcn/ui |
| "Показать еще" | open.js: slideToggle .article-hidd | useState в острове листинга |
| Табы Мужские/Женские | main.js, продублирован внутри plugins.js (копипаста) | остров |

- Известные уязвимости: jQuery 1.11.x - CVE-2020-11022/11023, CVE-2019-11358,
  CVE-2015-9251 (XSS через $.htmlPrefilter/extend). Для статического кита некритично,
  но в новый стек не тащим.
- Связанность: все селекторы зашиты в инлайн-скрипты в конце каждой страницы
  (index-journal.html:829-885); odd/even-классы навешиваются jQuery-ом
  (index-journal.html:848-853) вместо CSS nth-child; UA-sniffing на регэкспах
  (index-journal.html:830-836); инлайн-обработчиков on* нет (плюс).
- Своего кода - меньше 100 строк логики, копипастой размазанных по main.js/plugins.js.
  Терять нечего.
- Конфигуратор: в ките и в legacy отсутствует (подтверждено заказчиком - функциональность новая).

**Влияние на миграцию:** JS-слой не переносится совсем; каждый интерактив - маленький
React-остров, писать заново дешевле, чем разбирать плагины.

## 6. Стратегия переноса стилей (ADR-заготовка)

**Контекст.** Дизайн утвержден и сохраняется. Источник - статический кит des-2016 без
препроцессоров и методологии, с двумя дублирующими CSS-стеками, float-гридом и px-версткой.
Мертвого кода внутри стеков мало (~5%), специфичность простая, но межстековое дублирование
54% и дрейф палитры делают прямой перенос файлов бессмысленным.

**Рассмотренные варианты.**

1. *CSS Modules с сохранением существующих классов* - выгоден, когда есть выстроенная
   классовая система, которую жалко терять. Здесь ее нет: нейминг неконсистентен, стили
   раздвоены, грид float-овый. Пришлось бы сначала отрефакторить legacy-CSS, потом переносить.
2. *Tailwind-конверсия по токенам* - визуал воспроизводится утилитами от нормализованных
   токенов; каскад кита настолько прост (медиана специфичности 0,1,1), что потерь нет.
   Совместим с shadcn/ui из принятого стека.
3. *Гибрид: Tailwind для каркаса, CSS-слой для типографики статьи.*

**Рекомендация - вариант 3, по группам компонентов:**

- **Каркас, шапка, карточки, формы, сайдбары - Tailwind** от токенов раздела 5.
  Это 90% кита; здесь legacy-CSS не переносится вообще.
- **Тело статьи - @tailwindcss/typography (prose) + тонкий кастомный слой** для фирменных
  элементов статьи: врезки figure.sign/sign-right, hr-цитаты (hr.style-quote-first/last),
  p.summary, img-article с подписью. Это единственный фрагмент кита, где исходный CSS
  (general-main.css, секции статьи) стоит держать открытым как референс при написании
  prose-оверрайдов. Статья живет в MDX, поэтому стили должны работать от тегов, а не от
  классов - prose-подход это и дает.
- **Глобальный слой:** normalize.css не переносится (его роль выполняет preflight);
  fonts.css не переносится - PT Sans подключается через next/font/google (regular 400,
  bold 700, italic; лицензия OFL, файлы в репо не нужны); из глобального переносятся только
  токены (:root) и базовая типографика body (13-14px PT Sans, коричневый текст #482c17).
- **Не переносить:** flurid (заменяется CSS Grid: `grid-template-columns: 3fr 8fr 3fr` c
  gap по токенам), animate.css, owl-стили, datepicker.css, formstyler.css, foundation.css.

**Последствия.** Плюс: один источник правды по стилям, нулевой перенос долга, готовность
к shadcn/ui. Минус: каждый компонент требует визуальной сверки с китом (кит остается
эталоном для сравнения скриншотами); риск дрейфа от дизайна закрывается только
токен-дисциплиной. Решение о принятии - через /new-adr в ../journal-docs/adr.

## 7. Ассеты

- **Изображения -> next/image.** Реальные размеры исходников: логотип 240x125, баннер
  720x367, news-фото 600-1000px по ширине (до 300 КБ, img/news/12.jpg). Соотношения сторон
  в карточках фиксируются контейнером, в статье - произвольные; для тизеров нужен
  единый aspect-ratio (в ките он держится фикс-высотами). Placeholder blur нужен для
  крупных article-изображений; в MDX - обязательные width/height/alt через Zod-схему.
- **Шрифты -> next/font.** PT Sans доступен в Google Fonts (OFL) - локальные 3.3 МБ файлов
  не переносятся; нужны начертания 400, 700, italic. font-display решает next/font сам.
  Лицензий в legacy-репо нет - с next/font/google вопрос снимается.
- **Иконки.** В ките png-иконки (search.png, calendar.png, comment.png, стрелки меню) +
  классы FontAwesome без подключенного шрифта (fa fa-chevron, index-journal.html:54).
  Рекомендация: inline-SVG (lucide-react уже идет с shadcn/ui); png-иконки и иконочные
  шрифты не переносить.

## 8. Топ-10 рисков (что молча переедет, если не решить)

Дешево исправить в момент переноса (само ложится в переверстку):

1. **Нет h1 и иерархии заголовков** - перенос "как есть" гарантирует провал Lighthouse SEO.
   Чинится бесплатно при переверстке: div.news-title -> h1/h2 по месту.
2. **Два варианта шапки/футера** - если переносить по-страничо, дубль станет двумя
   React-компонентами и разъедется окончательно. Один Header/Footer с первого дня.
3. **Карточка книги x3 и тизер статьи x4** - каждый вариант, перенесенный отдельно,
   закрепляет дубли навсегда. Схлопнуть в компоненты с пропсами при первом же переносе.
4. **Формы без label/for/autocomplete/ошибок** - переверстка форм на shadcn/ui закрывает
   это автоматически; переносить старую разметку форм нельзя.
5. **Цветовой дрейф (51 цвет)** - если не зафиксировать токены до первого компонента,
   дрейф переедет в tailwind.config. Токены - раздел 5, утвердить до начала верстки.

Можно осознанно тащить и чинить потом:

6. **92% изображений без alt** - это контентный долг, а не долг вёрстки: тексты alt должен
   дать редактор. Механизм принуждения (обязательный alt в Zod-схеме фронтматтера) ставится
   сразу, наполнение - постепенно.
7. **px-вёрстка и 72 фикс-высоты** - на реальном контенте строки будут рваться не так, как
   в ките с рыбой. Переверстка убирает основное, но хвост (обрезка длинных заголовков,
   line-clamp) можно донастраивать по мере появления реального контента.
8. **Интерактив именин (datepicker, алфавит, табы)** - самый большой остров (L). Журналу
   для первой волны не нужен - можно осознанно отложить на вторую волну strangler-fig.
9. **Границы данных не размечены** - в ките захардкожены даты/цены/имена ("24 января 2016",
   index-journal.html:33). При разрезании на компоненты нужен контент-инвентарь: что
   статика, что фронтматтер MDX, что Postgres (цены/наличие - магазинный край). Ошибка
   здесь всплывет позже как "почему это не обновляется".
10. **Врезка книжной полки внутри статьи** - коммерческий блок в теле контента. Если не
    спроектировать его как MDX-компонент с данными из магазинного края сейчас, статьи
    мигрируют без него, и обратная вставка потребует правки всего контента. Решить до
    миграции контента: сохраняется ли блок и откуда берет данные.

Уходят сами при переносе (фиксирую для полноты): dojo.js-балласт, mixed content http://,
jQuery CVE, перезагрузка по resize, битый flurid.min.css, мертвые файлы.

## 9. Приложение: инструменты и команды (воспроизводимость)

```bash
# Инвентаризация
find $LEG -type f | sed 's|.*\.|.|' | sort | uniq -c | sort -rn   # файлы по расширениям
du -sh $LEG/{css,img,js,owlcarousel}                              # веса директорий

# Специфичность: пакет specificity@0.4.1, парсинг селекторов регэкспом
node spec.mjs                                                     # max (2,0,1), медиана (0,1,1), 1768 селекторов

# Метрики CSS грепами
grep -c '!important' $LEG/css/*.css
grep -hoE '#[0-9a-fA-F]{3,6}\b' <свои css> | tr 'A-F' 'a-f' | sort -u | wc -l   # 51 цвет

comm -12 <(селекторы main.css) <(селекторы general-main.css) | wc -l            # 88 общих

# alt-покрытие
for f in $LEG/*.html; do grep -o '<img' $f | wc -l; grep -oE '<img[^>]*alt=' $f | wc -l; done

# Веса gzip
for f in <подключаемые css/js>; do wc -c < $f; gzip -c $f | wc -c; done

# Размеры изображений (macOS)
sips -g pixelWidth -g pixelHeight $LEG/img/news/*.jpg
```
