# Карта рубрик нового журнала (дерево, зависимости, нейминг)

Дата: 2026-07-15. Источники: `legacy-rubrics.md`, `legacy-dump-checks.md`
(дамп 2018-11-17). Назначение: основа для TS-типов рубрик и схемы БД.
Нейминг НЕ выбран - для каждой сущности два варианта (транслит / перевод),
решение зафиксировать отдельным ADR.

## 1. Дерево рубрик

Глубина легаси - максимум 2 уровня (рубрика -> подрубрика). Месяц и имя -
не вложенность, а фасеты: списки по ним генерируются, не хранятся.

## 2. Зависимости

1. Житие -> источник: обязательная принадлежность (единственная настоящая
   подрубрика в модели); 3 жития-сироты без источника закрыть при миграции.
2. Житие -> даты памяти (0..3): питают месячные списки; сумма по месяцам
   1218 > 1199 из-за повторов - это норма, статья попадает в каждый свой месяц.
3. Именинная статья -> имя -> даты именин (таблица cal).
4. Поздравление -> имя: 89 поздравлений против 51+38 = 89 имен - похоже,
   ровно 1:1 с именинными статьями. Проверить при миграции; если так -
   связь делать жесткой.
5. Кросс-ссылки между рубриками (по `legacy-dump-checks.md` п.4): именинные ->
   жития соименных святых, поздравления -> именинные, главы Добротолюбия ->
   индекс. Все через `-lib<id>`, битых нет.
6. Архив изолирован: из корпуса articlex нет ссылок на старый журнал
   (`?article=` в body = 0), рубрики не пересекаются. Моделировать отдельной
   сущностью, в общее дерево не встраивать.

  URL-слаги - транслит (А), потому что легаси-URL уже транслитом
  (`zhitiya-svyatih`, `imenini`) и это непрерывность для SEO и редиректов.

## 4. Следствия для TS-модели (ориентир, не решение)

- Рубрика - конечный закрытый список: подходит union строковых литералов
  или enum; отдельная таблица категорий в БД легаси отсутствовала.
- Подрубрика есть только у житий - не делать универсальную рекурсивную
  вложенность ради одного случая.
- Фасеты (месяц, имя, пол) - поля статьи, не рубрики.
- Архив - отдельный тип со своим списком рубрик, не участник основного union.

# 5. Даты для статей
В легаси это два разных механизма хранения — и разница между ними поучительна.

  Жития: даты денормализованы в строку статьи

  В articlex под даты выделено 6 колонок + 1: dt1_day, dt1_month, dt2_day, dt2_month, dt3_day, dt3_month (smallint) и
  days_easter (tinyint). То есть жёсткий потолок — три даты, прямо на уровне схемы. Пустой слот — 0 или NULL
  (используются вперемешку: 0.0 и None означают одно и то же — типичная легаси-неаккуратность, конвейеру нормализовать).
  
  Живые примеры:
  - типичное житие: id=62 Василий Великий — dt1 = 14.01, остальные слоты пустые;
  - три даты: id=1382 Иоанн Златоуст — 26.11, 9.02, 12.02;
  - переходящие: id=1309 (лесбосские мученики) — все dt-слоты пустые, days_easter=2; id=1345 (икона «Трипити») —
  days_easter=5. Семантика — смещение в днях от Пасхи: вторник и пятница Светлой седмицы. Фиксированной даты у них нет
  вообще.

  Стиль календаря — новый (гражданский): Николай Чудотворец лежит как 19.12 и перенесение мощей 22.05 — это привычные
  «Никола зимний/вешний» по новому стилю. Пересчитывать ничего не надо, даты сразу пригодны для URL.

  Именины: даты вынесены в отдельную таблицу cal

  cal(id, dt_day, dt_month, obj, obj_id) — одна строка на одну дату, obj='ARTICLEX' (всегда), obj_id → именинная статья.
  1054 строки на 89 статей-имён, дублей нет.

  И вот почему легаси-автор не смог обойтись тремя слотами: у имени бывают десятки именин в году. Николай — 24 даты,
  Фёдор — 65, Иван — 108. Среднее — 11.8 дат на имя, минимум 1. Заметь: в cal нет аналога days_easter — именины только с
  фиксированными датами.
  
  Что из этого следует

  Легаси демонстрирует классику: пока кардинальность мала и ограничена (жития, ≤3), даты живут в строке; когда она
  взорвалась (именины, до 108) — появилась join-таблица. Автор налетел на потолок собственной схемы и решил его
  по-разному в двух местах.
  
  В файловой модели этого разлома не будет: фронтматтер — это YAML, массив там не имеет потолка ни в 3, ни в 108
  элементов. Обе сущности могут хранить даты одинаково — массивом {день, месяц} прямо в своём MDX-файле, а аналог
  таблицы cal (индекс «дата → статьи») становится вычисляемым на сборке — тем самым загрузчиком, который мы обсуждали.
  Единственное, что массивом не выражается, — переходящая дата: у неё вместо {день, месяц} живёт {смещениеОтПасхи} — две
  даты из 1199 потребуют, чтобы тип даты памяти был объединением двух форм.
