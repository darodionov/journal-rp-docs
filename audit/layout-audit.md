# Аудит верстки des-2016: качество и переносимость в Next.js

Дата: 2026-07-08. Объект: `legacy/des-2016` (read-only), статический HTML-кит,
реализующий макеты `graphic_design/Main_iDrp` (эталон дизайна - макеты, см.
`../design/graphic/main-idrp-design-audit.md`). Инструменты и команды - в
приложении. Все пути ниже - относительно `des-2016/`.

## Резюме

**Вердикт: переверстать.** Реюзу подлежат: дизайн-токены (палитра,
типографика, радиус - извлекаются, см. черновик), контентные изображения и
шрифты PT Sans, HTML-структура как референс блоков. Сам код верстки (CSS и
разметка) переносить нецелесообразно: две параллельные CSS-подсистемы с
дублированием (145 общих селекторов при текстовой близости файлов 0.37),
float-грид, все размеры в px, нулевая семантика и SEO-обвязка, классы-краски
`.blue`/`.brown` (1041 использование).

| # | Блок | Оценка | Ключевой факт |
|---|---|---|---|
| 1 | Семантика HTML | 2/5 | 0 тегов h1 на 11 из 12 страниц; 220-311 div на страницу |
| 2 | SEO-готовность | 1/5 | meta description пуст на всех страницах; OG/canonical/schema.org - 0 |
| 3 | Доступность | 2/5 | 93% img без alt; label без for; 164 кнопки без type |
| 4 | CSS-архитектура | 2/5 | 2 параллельные ветки CSS; 45 цветов (20 серых); методологии нет |
| 5 | Адаптивность | 3/5 | покрытие 320-1281 есть; float-грид, 1381 px-значение, 0 rem |
| 6 | Производительность | 2/5 | jQuery грузится дважды на 8 страницах (CDN + dev-сборка 295 КБ) |
| 7 | JS-слой | 3/5 | своего кода ~10 КБ (табы/тогглы) - тривиален; но jQuery-плагины и мертвый код |

Три главных вывода:
1. **Терпимо для 2016, блокирует цели 2026.** Отсутствие h1/меты/схемы и
   div-soup несовместимы с Lighthouse SEO >= 95; SEO-слой в Next.js строится
   с нуля - из верстки воспроизводить нечего (это упрощает миграцию).
2. **Дизайн-система извлекается.** Палитра консолидируется в ~10 канонических
   цветов (остальное - дрейф), типографика - 8 ступеней, радиус один (3px).
   Это система с дрейфом, не хаос - Claude Design получит чистый вход.
3. **Кит неполон относительно целевой системы.** Есть только журнал + именины
   (12 страниц): магазина (каталог/карточка/корзина/чекаут) и конфигуратора
   в des-2016 НЕТ - для них аудитовать нечего, верстка появится позже.

Природа: **статический HTML-кит от верстальщика**, PHP-вкраплений 0 (grep
`<?php` - пусто), inline-обработчиков 0, inline-style 0. Кодировка UTF-8.
Контент захардкожен - границы данных придется определять по макетам, не по коду.

Методология: **отсутствует**. БЭМ-классов с `__` - 0 из 203 уникальных
классов; нейминг смешанный (`section-item_h3`, `buy_btn`, `news-title`);
верх частотности - классы-краски `.blue` (643 вхождения) и `.brown` (398).

Красный флаг (зафиксирован, не блокер): **две параллельные CSS-подсистемы**.
Журнальные страницы подключают general-main + general-media + flurid-грид;
именинные - main + media + datepicker, без грида. Обе ветки живые, каждая
обслуживает свой куст страниц; общие блоки (шапка, футер, сайдбары, товарные
карточки) сверстаны дважды с дрейфом: 145 общих селекторов, текстовая
близость файлов 0.37 (например, `.day-date` в main.css:305 и
general-main.css:386; `.logo` в main.css:312 и general-main.css:393).

## Фаза 1. Качество верстки

### 1. Семантика и структура HTML - 2/5

- div-soup: 305 div при 4 семантических тегах в article-01.html; 311/1 в
  rubrika.html; 297/1 в index-journal.html. Роли вместо тегов:
  `<div role="banner">` (article-01.html:43), `role="navigation"` (:47),
  `role="main"` (:115), `role="contentinfo"` (:835) - валидатор выдал 44
  prefer-native-element.
- Заголовки: **h1 есть только на 404.html**. На журнальных страницах
  h-тегов НЕТ вообще (0 на article-01, index-journal, rubrika - заголовок
  статьи сверстан div-ами); именинные начинаются с h2 (5-6 шт) + h5 (2) с
  пропуском уровней.
- Валидатор (html-validate, recommended): 1968 ошибок на 12 файлов.
  Реальные проблемы: 102 незакрытых li (article-01.html:121-122...),
  8 дублей id="form" (birthday*.html:333-394), 1 stray `</p>`
  (article-01.html:151), `<figure>` внутри `<p>` (article-01.html:401, 412),
  li внутри div (index-birthday.html:88-90); остальное - стиль (937
  trailing-whitespace, 110 условных комментариев IE, 73 self-closing void).
- Влияние на миграцию: разметка непереносима as-is; семантический каркас
  (article/header/main/nav) пишется заново - трудозатраты уходят в
  переверстку, не в адаптацию.

### 2. SEO-готовность - 1/5 (критично для журнала)

- `<title>` есть на всех 12; **meta description присутствует, но пуст**
  (`content=""`) на всех контентных страницах.
- Open Graph: 0 вхождений на всех страницах. Canonical: 0. schema.org
  (Article/BreadcrumbList/Product): 0.
- alt: article-01 - 39 из 43 img без alt (91%), rubrika - 36/37 (97%),
  index-journal - 32/33 (97%), именинные - 16/18 (89%).
- Хлебных крошек нет (совпадает с макетами - там их тоже нет).
- Влияние на миграцию: **SEO-обвязка в верстке отсутствует полностью** -
  в Next.js Metadata API, JSON-LD и canonical строятся с нуля по данным
  legacy-БД (см. legacy-map.md), из кита не переносится ничего. Это чистый
  лист, а не порча.

### 3. Доступность - 2/5

- Формы: label есть (birthday.html: 4), но с for= только 2 из 4; в
  index-journal и article-01 label без for вовсе (0 из 4 и 0 из 2).
  autocomplete: 0 на всех формах (валидатор: 11 autocomplete-password).
  8 страниц с дублем id="form" ломают связывание.
- Кнопки: 164 button без type (no-implicit-button-type); 11 мест с
  div/span вместо button (prefer-button), например бургер
  `.material-menu-button` - div со span-ами.
- Фокус: 11 вхождений `outline: none/0` в своих CSS без замены стиля фокуса.
- ARIA: role-атрибуты дублируют будущие нативные теги (30 no-redundant-role),
  22 unique-landmark (несколько role="navigation" без label).
- Клавиатура: меню/табы/аккордеоны - клики по div (js/plugins.js:29
  `$('.thead').click`), с клавиатуры недоступны.
- Влияние на миграцию: паттерны интерактива переписываются на
  Radix/shadcn-примитивы - в них a11y бесплатно; тащить нечего.

### 4. CSS-архитектура - 2/5

- Методология: нет (см. фазу 0). Классы-краски .blue/.brown - 1041
  использование в HTML.
- Специфичность: умеренная. Максимум - 4 составных части
  (main.css:793 `.scroller-vertical .section-item .section-item .price-wrap`);
  49 правил с #id (main.css:836-882 `#form ...` и парные в general-main.css).
  !important - всего 12 (по 6 в main.css:1085,1136-1139,1176 и
  general-main.css:948,999-1002,1039) - каскадных войн нет.
- Дублирование: главный дефект - межфайловое (две ветки, 145 общих
  селекторов). Внутри веток мертвого кода мало: purgecss по всем 12
  страницам + JS отсекает лишь 4-5% из main/general-main и <1% из media.
  Зато вендорные animate.css (72 КБ) - 0 использующих классов в HTML,
  foundation.css (24 КБ) и jquery.formstyler.css - не подключены вообще.
- Битые пути: main.css:392,399,405,749,768 - `url(/__/img/icon_icon.png)`,
  `url(/__/img/video1.png)`, `url(/__/img/comment.png)` - абсолютные пути
  на несуществующую в ките папку `/__/` (иконки видео/комментариев товарных
  карточек не загрузятся).
- z-index: шкала [1, 9, 10, 99, 9999] - двухуровневая реальность (контент /
  оверлей), 9999 - магическое число (main.css, media.css, general-*).
- Токены: **система с дрейфом, извлекаемая**. 553 hex-вхождения, 45
  уникальных цветов, из них 20 серых (r=g=b) - дрейф вокруг ~4 серых ролей;
  бирюза в 3 вариантах (#65c6cd 25, #8bc8cf 55, #8cc8d0 13), терракота в 4
  (#dca28c 23, #c09983 23, #daa384 6, #dda189); якоря стабильны: #482c17
  (53), #ebebeb (92). Типографика: 8 px-ступеней (10/12/13/14/15/16/18/20) +
  выбросы 80px и 2em/2.3em; interline 0.7em-1em (подозрительно плотно,
  местами <1). Радиус единственный: 3px. Теней 8 уникальных. Шкалы отступов
  нет (значения произвольные).

### 5. Адаптивность - 3/5

- Подход: desktop-first с max-width перекрытиями + диапазонные запросы;
  сетка журнала - Flurid (float-грид с классами `width_14/16`, 59 вхождений
  column), именинная ветка - ручные float (71 float против 8 flex, grid - 0).
- Брейкпоинты: неединообразны между файлами. Фактический набор:
  320 / 321 / 480 / 767 / 768-950 / 950-951 / 1223-1224 / 1280-1281; в
  general-media.css диапазон 951-1223+1224-1280, в media.css - 951-1280
  одним куском. Плюс `@media \0screen` (хак IE8) в обоих.
- Единицы: 1381 px-значение, rem - 0, em - 35. Фиксированные высоты - 76
  вхождений height:Npx - ловушки при переносе на другую типографику.
- Покрытие макетов: полное (320/768/1600+) - редкий плюс; макеты и верстка
  бьются по брейкпоинтам 320/768.
- Влияние на миграцию: сетки переезжают на flex/grid с нуля; сами точки
  останова упростить до 2-3 канонических.

### 6. Производительность фронта - 2/5

- CSS на журнальной странице: 9 файлов, ~174 КБ raw / ~21 КБ gz, из них
  animate.css 72 КБ raw (4.4 КБ gz) - мертвый груз, flurid 24.5 КБ.
- JS на именинной странице: **jQuery загружен дважды** - CDN 1.11.3.min +
  локальная незминифицированная jquery-1.11.3.js (295 КБ raw / 86 КБ gz)
  (birthday.html: подряд две строки script). На журнальных вместо этого -
  **Dojo 1.11.2 с CDN** (article-01.html:1-я секция скриптов), который не
  используется ни одним скриптом (grep dojo по js/ - 0) + jquery-1.11.2.min
  локально. Итого именинная страница: ~510 КБ JS raw (~150 КБ gz) без CDN.
- Render-blocking: все 9 CSS + 2-3 JS в head без defer/async (кроме
  подгрузки контентных скриптов в конце body).
- Изображения: WebP/AVIF - 0, srcset/picture - 0; превью новостей грузятся
  оригиналами 600-1034px (img/news/12.jpg - 297 КБ, 10.jpg - 214 КБ).
- Шрифты: 5 форматов x 3 начертания (~2.4 МБ в репо; браузеру уходит woff),
  font-display - нет; начертания подключены как отдельные family
  ('ptsans','ptsansbold','ptsansitalic' - css/fonts.css:1-28) вместо
  font-weight - типографические веса в CSS размазаны по family-именам.
- jQuery 1.11 (2015): известные CVE (XSS в $.html/selector interp - CVE-2015-9251,
  CVE-2019-11358 и далее) - в новый стек не едет в любом случае.

### 7. JS-слой верстки - 3/5

- Что делает свой код (~10 КБ): табы имен (plugins.js:26-36 - клики по
  .thead), переключение секций сайдбара тремя обработчиками с ручным
  add/removeClass шести классов (plugins.js:40-58), slideToggle «показать
  больше» (open.js), анимация поисковой строки (search.js). Инициализация -
  4 inline-script на страницу (детект мобильных по UA, materialmenu, owl).
- search.js использует `$.browser` (search.js:22,31...) - API удален в
  jQuery 1.9: код мертв с подключенными версиями; сам файл не подключен ни
  к одной странице (как и main.js на большинстве - он продублирован внутрь
  plugins.js).
- Селекторы зашиты в JS: `.names .thead`, `.section-mos-visible` и пр. -
  хрупкая связка, но объем тривиален: в React это 3 useState.
- Меню - кастомный jQuery-плагин materialmenu (16 КБ) - заменяется
  Sheet/Drawer из shadcn.
- Конфигуратор: **в ките отсутствует** - оценить отделимость логики от DOM
  невозможно, аудит будет нужен отдельно, когда появится код.
- Влияние на миграцию: весь UI-JS - выброс и переписывание на
  React-примитивы; ценного алгоритмического кода нет.

```js
    fontSize: {
      xs: "12px", sm: "13px", base: "15px", md: "16px", lg: "18px", xl: "20px",
    },
    borderRadius: { DEFAULT: "3px" },
    letterSpacing: { nav: "0.12em" }, // капс-навигация макетов
  },
  screens: { sm: "480px", md: "768px", lg: "1024px", xl: "1280px" },
}
```

Чего в легаси НЕТ (задать в дизайн-системе с нуля): шкала отступов
(в CSS произвольные px), содержательные line-height (легаси 0.7-1 -
слишком плотно, для статьи задать 1.6-1.7), тени (8 разрозненных -
консолидировать до 2-3), состояния hover/focus.

### 2.3 Стратегия переноса стилей (заготовка ADR)

Контекст: код верстки непереносим (две ветки, float, px, классы-краски),
но токены извлекаемы и дизайн утвержден. Стилевое решение нового стека не
выбрано; CLAUDE.md фиксирует Tailwind + shadcn/ui как рабочий ориентир стека.

Варианты по группам:
1. **Компоненты UI (карточки, шапка, формы, сетки)** - Tailwind-конверсия
   по токенам из 2.2. Аргументы: токенов мало и они ложатся в theme без
   остатка; переверстка все равно полная (реюз классов - 0, легаси-классы
   семантики не несут: .blue/.brown); shadcn/Radix закрывает a11y-дыры
   легаси бесплатно. CSS Modules дал бы что-то только при переносе готовых
   стилей - переносить нечего.
2. **Типографика статьи (тело, pull-quote, врезки)** - глобальный слой:
   @tailwindcss/typography с кастомизацией под токены (или отдельный
   article.css при отказе от Tailwind). Это единственное место, где стиль
   привязан к контенту (HTML из MDX/БД), а не к компонентам.
3. **Глобальное (reset, шрифты)** - normalize.css легаси заменяется
   Tailwind preflight (или modern-normalize); fonts.css заменяется
   next/font/local (PT Sans regular/bold/italic woff2, веса вместо трех
   family). Из легаси в глобальный слой не едет ничего.
4. **Переверстать без опоры на легаси** - все именинные интерактивы
   (формы, календарь, табы) и все, чего в ките нет (рубрика, пагинация,
   поиск-результаты, 404-дизайн).

Рекомендация: **Tailwind CSS + shadcn/ui для всего** (вариант 1+2+3),
CSS Modules не использовать. Решение оформить ADR-ом «Стилевое решение
нового стека» на базе этого раздела (не принято до ADR).

### 2.4 Ассеты

- **Изображения -> next/image.** Контентные превью (img/news, 600x337 и
  1000x384+) - это контент статей: в новом стеке идут из
  контент-пайплайна с автогенерацией размеров; для карточек нужны
  соотношения 16:9 (превью) и ~1:1.07 (иконы товаров 200x234). Placeholder
  blur - для крупных фото статьи и карточек. WebP/AVIF даст next/image
  сам. Дизайн-ассеты для переноса: логотип (img/logo.jpg - в вектор!),
  соцкнопки, орнаментальные кавычки.
- **Шрифты -> next/font/local.** woff2 всех трех начертаний в ките есть
  (112/64/92 КБ). Лицензий в репо НЕТ; PT Sans распространяется под
  OFL/ParaType Free - формально ок, но файлы лицензии добавить в новый
  репо. eot/svg/ttf не переносить.
- **Иконки.** В легаси - зоопарк: PNG-фоны (img/search.png,
  mainmenu-arrow*.png), base64-PNG в CSS (main.css:955), псевдо-fa классы
  без Font Awesome (i.fa-chevron стилизуется вручную -
  general-media.css:77). Рекомендация: inline-SVG (lucide-react +
  2-3 кастомных: кавычки, герб) - спрайт/иконошрифт не нужны.

### 2.5 Топ-10 рисков (что молча переедет, если не решить)

Чинить в момент переноса (дешево сейчас, дорого потом):
1. Отсутствие h1/иерархии заголовков - перенос «как в макете» без
   семантического слоя повторит SEO-провал (макеты про визуал, не про h1).
2. Пустые description / нет canonical / нет schema.org - если не заложить
   в контентный пайплайн поля мета с первого дня, журнал уедет без них.
3. alt-тексты - 93% картинок без alt; в MDX-миграции нужно поле alt в
   контенте, иначе дыра воспроизведется автоматически.
4. Классы-краски как способ мышления (`.blue`, 643 шт) - при «быстрой
   конверсии» превращаются в text-[#65c6cd] россыпью; лечится только
   токенами в theme.
5. Две версии общих блоков (шапка/футер/карточки) - переносить строго из
   одного источника (макеты), не из двух CSS-веток, иначе дрейф переедет.
6. Плотный interline (0.7-1) и px-типографика - буквальный перенос даст
   нечитаемую статью; типографику статьи проектировать заново (prose).
7. Фикс-высоты (76 шт) в карточках - в React-сетках дадут обрезание
   текста на реальных данных (легаси жил на lorem-заглушках).
Осознанно отложить (не блокирует):
8. Товарные блоки - до Medusa рендерить статикой/заглушкой; риск - завязать
   журнальные шаблоны на живой магазин раньше времени.
9. Соцшаринг-виджеты (FB/VK живые скрипты) - заменить статичными
   share-ссылками; полноценные виджеты - никогда (вес + приватность).
10. Датапикер/календарь именин - вертикаль отложена; не тащить jQuery
    datepicker временно «чтобы было» - подождет React-решения.
