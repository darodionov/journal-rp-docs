# ADR-0008: Режим «журнал без живого магазина» — товарные поверхности, полка, ссылки chrome

- Статус: Принято
- Дата: 2026-07-24
- Уточняет: Дополнение к программе (реш. 2 и 3); опирается на ADR-0003, ADR-0007

## Контекст

Товарные поверхности вшиты в утверждённые шаблоны журнала: товарный блок
«Библиотека» в правом сайдбаре статьи и главной, на 768/320 — тот же блок
врезкой внутри тела статьи (`Biblioteka_320_1/2`), товарные ряды на главной.
Убрать их — верстать не по макету. Живого магазина при этом нет: он мигрирует
после журнала (Medusa, недели 11–13), источник данных о товарах сменится
дважды. Аудит дизайна (п. 6) требует решить режим «журнал без живого
магазина» до вёрстки шаблонов — этот ADR и есть то решение.

Ревизия 2026-07-24 добавила два обстоятельства, не учтённых в реш. 2
дополнения: (а) полка — один набор товаров с двумя размещениями (сайдбар
≥ lg / врезка в теле < lg), поэтому формулировка «MDX-компонент
`<BookShelf ids={[...]}/>`» не работает: сайдбар — зона шаблона страницы и
тело MDX не читает; (б) владелец готов сам написать PHP-сторону на действующем
сайте, что открывает более дешёвый путь ко второй стадии источника, чем прямое
MySQL-чтение из Node. Плюс в chrome живут сквозняки магазина (Вход/Регистрация,
«Магазин книги», текст-визитка и 8-800 в футере, Ctrl+Enter), судьба которых
не была записана.

## Решение

1. **Режим:** товарные поверхности работают на fake-источнике за портом —
   не скрываются и не заменяются визуальной заглушкой. По таксономии
   тест-дублёров это именно fake: работающая реализация с упрощённой
   начинкой, а не stub-картинка.
2. **Товары — вне контента.** В MDX и фронтматтере статей нет ни данных,
   ни идентификаторов товаров. `<BookShelf/>` — серверный компонент
   шаблона страницы (не MDX-компонент): сайдбар ≥ lg, врезка в теле < lg,
   один набор. Состав полки определяет источник, а не статья — как на
   действующем сайте, где блок сайдбара общесайтовый.
3. **Порт `ProductSource`** — модуль домена `src/lib/products/` по
   дисциплине ADR-0007: `index.ts` (публичная точка), `product-source.ts`
   (порт), `fixture-source.ts` (адаптер), `schema.ts` (Zod = домен,
   типы через `z.infer`), тесты. Доменный тип `ProductCard`: id, обложка
   (src, alt, width, height — урок аудита), автор, название, цена,
   отзывы (count, hasVideo), href покупки. Интерфейс первой очереди —
   `getShelf()` (набор полки); `getByIds` не заводится без сценария
   (санитарная проверка ADR-0007).
4. **Данные фикстур** — JSON на диске вне `src/`: `content/products/*.json`
   (граница «код/данные» — как у статей, ADR-0007 п. 1). Генерирует
   Claude Code (правило 1 режима обучения); Zod-схема владельца их
   валидирует — расхождение роняет тест, это проверка контракта.
5. **Стадии источника:** `FixtureProductSource` (JSON с диска, шаг A10) →
   `LegacyHttpProductSource` (HTTP-endpoint на действующем PHP-сайте,
   отдаёт UTF-8 JSON той же формы;) →
   `MedusaProductSource` (неделя 13; критерий демонтажа: endpoint на
   легаси выключен). **Фикстурные JSON — wire-контракт endpoint'а:**
   PHP обязан отдавать форму, проходящую ту же Zod-схему.
   Это уточняет реш. 2 дополнения (прямое read-only MySQL-чтение из
   Node снимается: кодировочный шов остаётся на PHP-стороне, где код
   одноразовый) и усиливает реш. 3: cp1251 не пересекает границу нового
   стека вообще. Далее перенесем чтение из базы.
6. **Рендеринг:** серверные карточки; в A10 — чистый SSG, ISR-механика —
   B6 (без изменений). Клиентское в полке — только скролл карусели
   (CSS scroll-snap). Механизм двух размещений (двойной рендер со
   скрытием по `lg` или альтернатива) — решить при вёрстке A11/A12 и
   записать; позиция врезки в теле < lg — фиксируется шаблоном, принять
   при вёрстке A12.
7. **Политика ссылок chrome — три стадии:** (1) заглушка `href="#"` —
   сейчас; (2) внешняя ссылка на действующий сайт — как только владелец
   даст URL; (3) внутренний маршрут — по мере миграции раздела.
   Затронуты: О нас, Контакты, Вход/Регистрация, Магазин книги, События,
   Паломничество. Кнопка «В корзину» — та же политика: стадия 2 = якорь
   на карточку товара действующего магазина (href приходит из
   `ProductCard`, т.е. решается источником, не вёрсткой).
8. **Сквозняки футера:** текст-визитка магазина и 8-800 — остаются
   (статичный бренд-контент, вреда нет). «Ctrl+Enter» — убрать до
   появления механизма репортов: мёртвое обещание хуже отсутствия
   (триггер возврата — см. ниже). ⚠ Пункт на подтверждение владельцем.

## Рассмотренные альтернативы

- **Скрыть товарные блоки до миграции магазина** — отвергнуто: A11–A13
  верстаются не по макету, каждую поверхность придётся достраивать
  повторным заходом в каждый шаблон.
- **Визуальная заглушка (stub-картинка «здесь будут товары»)** —
  отвергнуто: UI врёт, подключение живых данных = перевёрстка;
  контракт данных не проверяется до недели 11.
- **Идентификаторы товаров в контенте** (исходная формулировка реш. 2:
  MDX/фронтматтер) — отвергнуто для текущего поведения: набор полки
  общесайтовый, кураторства пер-статью на действующем сайте нет; сайдбар
  как зона шаблона не читает тело MDX. Возврат — триггером пересмотра.
- **Прямое read-only MySQL-чтение из Node на стадии 2** (исходное
  реш. 2) — отвергнуто: тащит в новый стек драйвер, детектив с
  кодировками и временный шов к чужой БД; PHP-endpoint локализует всё
  это на стороне, которая и так умирает.

## Последствия

- (+) Контент чист от коммерции: конвейер B1 о товарах не знает вовсе.
- (+) Подключение живого магазина: сделать придётся — PHP-endpoint
  (владелец) и `LegacyHttpProductSource` + переключение точки входа;
  делать НЕ придётся — править статьи, перевёрстывать полку, менять
  `BookShelf` или шаблоны. Смена на Medusa — та же операция ещё раз.
- (+) Карточки индексируются (server-HTML), статья остаётся SSG.
- (−) Полка одинакова на всех статьях — приемлемо: действующий сайт
  живёт так же.
- (−) Двойной рендер полки в DOM (desktop+mobile копии) — дёшево при
  нулевом JS; принять окончательно в A12.
- (−) Риск дрейфа формы фикстур от реальных данных — закрыт направлением
  зависимости: не схема подгоняется под легаси, а PHP-endpoint под схему.
- Уточнение 2026-07-25 (ADR-0009 п. 6): в мигрированном легаси-контенте
  временно сохраняются /buy/-вставки (решение владельца) — явное исключение
  из п. 2 с критерием демонтажа при миграции магазина; „конвейер B1 о
  товарах не знает вовсе" сужается до „конвейер не создаёт товарных данных
  и не выносит их во фронтматтер".

## Триггеры пересмотра

| Триггер | Ожидаемое изменение |
|---|---|
| Нужна пер-статейная подборка книг | `books: [id]` во фронтматтере + `getByIds` в порте; дополнение к этому ADR |
| Неделя 13: Medusa | `MedusaProductSource`; legacy-endpoint выключен (критерий демонтажа) |
| Появился механизм репортов об опечатках | Вернуть «Ctrl+Enter» отдельным решением |
| Владелец дал URL разделов/товаров легаси | Массовый переход ссылок на стадию 2 (правка констант, не вёрстки) |
| Миграция магазина (нед. 11–13) | Переписать или вырезать /buy/-вставки в контенте — ADR-0009 п. 6, чек-лист недели 18 |
