# ADR-0003-m: Рубрики и источник житий для мигрированных статей

- Статус: Предложено (черновик наставника по решению владельца 2026-08-31,
  вариант 1А; пункты с ⚠ — на подтверждение владельцем при коммите)
- Дата: 2026-08-31
- Серия: m-ADR миграции (после 0001-m «Динамика главной» и 0002-m
  «Раскладка медиа миграции», он же ADR-0010)

## Контекст

Схема арки A (`src/lib/content/schema.ts`) — discriminated union по полю
`rubrika` с четырьмя вариантами: `zhitie`, `russkiy_palomnik`, `imeniny`,
`dobrotolyubie`. Корпус B1 несёт девять типов статей (1:32, 2:8, 3:18,
4:1199, 5:18, 6:1, 17:66, 20:2, 26:1), и шести из них дома в схеме нет.
Дерево `rubrics-taxonomy.md` (2026-07-15) уже назначило дом каждому типу:
жития с подрубрикой-источником, Добротолюбие, «Русский Паломник» и семь
малых плоских рубрик. `corpus.jsonl` несёт и `type` числом, и `rubrika` /
`razdel_zhitiy` словами (LEFT JOIN к `dic_data`; сирота справочника едет
NULL-ом и обязана громко падать на S8). Раскладка `src_saints` по корпусу:
{0: 149, 1: 5, 2: 41, 3: 1148, 4: 2}; житий с нулевым источником — три,
таксономия велит «разнести при миграции». Гейт записан в DEBT-B
(строка от 2026-08-27 «карта соответствия для S8»).

## Решение

1. **Enum рубрик расширяется до девяти корпусных значений.** К четырём
   существующим добавляются `statya`, `pritcha`, `nastavlenie`,
   `biografiya`, `akafist`, `molitva` — значения-данные транслитом в
   snake_case по ADR-0006 п. 1. Каждый новый вариант схемы строится по
   образцу `russkiyPalomnikSchema`: `baseArticleSchema.extend({ rubrika:
   z.literal(...), legacyId: z.int().positive().optional() })`.
   Продуктовая цена принята осознанно: рубрики-одиночки (молитвы — 1
   статья, биографии — 1, акафисты — 2) станут страницами-карликами в B2;
   как их показывать в навигации — решение вёрстки B2, данные типа при
   этом не теряются и обратной склейки не потребуют.

2. **Карта «тип → рубрика» живёт в коде стадии S8** и сторожится
   компилятором — приём `subset.ts`:

   ```ts
   const RUBRIKA_BY_TYPE = {
     1: 'statya',        // Статьи
     2: 'pritcha',       // Притчи
     3: 'nastavlenie',   // Наставления
     4: 'zhitie',        // Жития святых
     5: 'russkiy_palomnik', // о журнале
     6: 'biografiya',    // Биографии
     17: 'dobrotolyubie',
     20: 'akafist',
     26: 'molitva',
   } satisfies Record<CorpusType, Rubrika>;
   ```

   Ключ — тип-число (первичный носитель смысла в легаси); слово `rubrika`
   из `corpus.jsonl` в маппинге не участвует и идёт только в причины
   карантина и отчёт. Пустое или NULL слово при живом типе — сирота
   справочника, карантин с самодостаточной причиной. Тип вне карты
   до S8 доехать не может (S1 убила бы прогон), но сторож формы записи
   корпуса обязан проверить это заново: корпус правится руками.

3. **Источник житий.** Для `rubrika: 'zhitie'` обязательный `istochnik`
   строится картой `ISTOCHNIK_BY_SRC = { 1: НиколайСербский, 2: Избранные,
   3: ДимитрийРостовский, 4: ЗемнаяЖизнь }` (точное написание значений —
   п. 4). `src_saints` жития вне 1..4 — в том числе 0 «без источника» —
   даёт **карантин** с причиной вида: «житие без источника (src_saints=0):
   назначить руками — выставить src_saints и razdel_zhitiy в corpus.jsonl
   отдельным коммитом». На полном корпусе таких статей три, в подвыборке
   носителя нет — ветка закрывается намеренной поломкой приёмки.
   У не-житий `src_saints` игнорируется (у типа 1 встречается 0 со словом
   «-» — это норма).

4. ⚠ **Написание значений `istochnik` — привести к ADR-0006.** Сейчас
   схема A4 несёт PascalCase (`DimitryRostovsky`, `NikolaiSerbsky`,
   `Izbrannye`, `ZemnayaZhizn`), а ADR-0006 п. 1 велит значениям-данным
   snake_case транслит. Предложение: переименовать в `dimitry_rostovsky`,
   `nikolai_serbsky`, `izbrannye`, `zemnaya_zhizn` СЕЙЧАС, пока значения
   не разошлись по 1199 статьям; правка — `schema.ts`, `schema.test.ts` и
   рукописные жития арки A, если они есть. Альтернатива — узаконить
   PascalCase эрратой к ADR-0006. Решает владелец при коммите.

5. ⚠ **Дни памяти — в базовую схему.** DEBT-карта велит нести
   `datyPamyati ← dt1..dt3` и `fromEaster ← days_easter`, но поля живут
   только у `zhitie` (и `imeniny`). Данные показывают дни памяти и у
   не-житий: статья 71 (тип 1, «Лествица») несёт 12.04 — память Иоанна
   Лествичника. Предложение: перенести `datyPamyati` и `fromEaster` в
   `baseArticleSchema` опциональными (у `imeniny` остаётся `.min(1)`);
   S8 пишет их любой рубрике из непустых слотов. Механика слота: пустой =
   0 или NULL (в легаси вперемешку); слот берётся при `day ≥ 1 && month ≥ 1`;
   `days_easter` пишется в `fromEaster` при значении, отличном от NULL.
   Альтернатива — нести только житиям и терять у остальных со строкой
   отчёта. Решает владелец.

## Рассмотренные альтернативы

- **1Б: свёртка малых типов в одну рубрику «статьи».** Навигация без
  карликов, но различие притч, молитв и акафистов стирается в данных
  навсегда (восстановимо только повторным заходом в легаси по legacyId),
  а июльская таксономия отменяется молча. Отвергнуто владельцем.
- **Карта в отдельном файле данных.** Девять строк — это решение, а не
  данные; `satisfies` в коде даёт проверку полноты бесплатно. Отвергнуто.
- **Маппинг по словам dic17.** 27 значений, парсить слова хрупко;
  тип-число первичен. Слова — только в отчёт и причины. Отвергнуто.
- **Пятое значение `istochnik` «без источника».** Легализует дыру в
  данных против прямого указания таксономии «разнести при миграции».
  Отвергнуто.
