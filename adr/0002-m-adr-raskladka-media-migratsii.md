# ADR-0010: Раскладка медиа мигрированных статей — сохранение легаси-путей в `public/`

- Статус: Принято
- Дата: 2026-08-29
- Уточняет: ADR-0007 (целевое дерево, узел `public/images/<slug>/...`).
  Опирается на ADR-0009 п. 6 (товарные вставки сохраняются как есть),
  ADR-0008 (товары — вне контента), декомпозицию B1 (решение 3 —
  собственность конвейера; стадия S6), разведку
  `ark-b/investigations/2026-08-29-images-inventory.md`; решения владельца
  от 2026-08-29.

## Контекст

ADR-0007 назначил картинкам статей дом `public/images/<slug>/...`: одна
статья — одна папка. Правило писалось для рукописных статей арки A, где автор
кладёт свои файлы рядом со своим слагом, и там оно остаётся верным.
Мигрированный корпус устроен иначе, и разведка 2026-08-29 это показала:

- В телах 1338 статей — 354 уникальных редакционных адреса в четырёх
  легаси-корнях: `/images/content` (346), `/htm/zhitiya-pic` (6),
  `/htm/fair/html` (1), `/pages/article/all/av` (1). Все 354 файла лежат в
  локальном зеркале веб-корня старого сайта (`../legacy` относительно
  репозитория журнала).
- Файлы общие на группы статей: обложка собрания из `/htm/fair/html/ignatii/`
  процитирована шестью статьями, числовые картинки `image/N.jpg` делят серии
  житий. Раскладка «папка на слаг» размножила бы один файл по числу
  цитирующих статей.
- Адреса в телах после стадии S5 уже приведены к корневой форме
  (`/images/content/image/230.jpg`), а компонент `Figure` при сборке
  складывает `public/` с этим адресом и сам читает размеры из файла.
  Переписывать адреса некому и незачем.
- Товарные картинки (156 уникальных адресов: `/buy/content/products/...` и
  две обложки в корне сайта) в зеркале отсутствуют целиком; по ADR-0009 п. 6
  товарные вставки сохраняются как есть, адреса получают домен
  `https://idrp.ru` (отдельная строка DEBT-B о `remotePatterns`).

Мерило прежнее (ADR-0007): структура промышленна тем, какие изменения делает
дешёвыми. Дёшевы должны быть перепрогон конвейера, добор статей в B5 и будущий
перенос товарных картинок при миграции магазина.

## Решение

1. **Редакционные картинки мигрированных статей лежат в `public/` по
   неизменённому легаси-пути.** `/images/content/image/230.jpg` →
   `public/images/content/image/230.jpg`; так же для `htm/zhitiya-pic/...`,
   `htm/fair/html/...`, `pages/article/all/av/...`. Адрес картинки на новом
   сайте равен её легаси-адресу; строки `src` в MDX не переписываются.
2. **Две раскладки сосуществуют.** `public/images/<slug>/...` (ADR-0007)
   остаётся домом картинок рукописных статей. Легаси-корни объявляются
   зарезервированными именами: `public/images/content/` целиком,
   `public/htm/`, `public/pages/` (и `public/buy/` на будущее). Рукописной
   статье нельзя иметь слаг `content`: папка `public/images/content/` занята.
3. **Копирует конвейер — стадия S6 (`copy_img`), только редакционные
   адреса** (`kind: editorial` из `s5-mdx.jsonl`) из локального зеркала
   веб-корня. Товарные адреса не копируются и остаются абсолютными ссылками
   на `idrp.ru` (ADR-0009 п. 6). Копируются только файлы, на которые
   ссылаются тела, а не каталоги целиком: лого, служебная графика и
   миниатюры `_thumb/` не переносятся.
4. **Размеры конвейер не измеряет и не хранит.** Контракт: для каждого
   редакционного `src` мигрированной статьи файл `public/<src>` существует и
   читается `Figure` при сборке. Контракт сторожит S6: файла нет в зеркале →
   карантин статьи (сборку не роняем); нет каталога зеркала или публичной
   папки → смерть прогона.
5. **Скопированные файлы — собственность конвейера** (решение 3
   декомпозиции): S6 ведёт манифест, при перепрогоне удаляет из `public/`
   только перечисленное в манифесте прошлого прогона и никогда не трогает
   файлы, положенные руками (картинки арки A).
6. **Файлы коммитятся в репозиторий.** Зеркало живёт только на машине
   владельца; любая сборка вне неё — CI, хостинг, второй компьютер — получит
   файлы только из git. Оценка по разведке: 354 файла полного корпуса —
   порядка 9 МБ (911 файлов `/images/content` весят 22 МБ); на подвыборке —
   десятки файлов.
7. **Зеркало — вторая ручная предпосылка прогона** рядом с `corpus.jsonl`:
   путь задаётся переменной окружения (имя — в `config/media.ts`, умолчание
   `../legacy`), в git не входит. Критерий «Готово» п. 1 декомпозиции
   дополняется этой предпосылкой.

## Открыто (закрыть до перевода в «Принято»)

- **Форма записи скобок.** В корпусе есть адрес `4_%282%29.jpg`, на диске
  файл `4_(2).jpg`. Для браузера это один адрес, для файловой системы — два
  разных имени; `Figure` складывает `src` с `public/` без декодирования. Либо
  S5 пишет в MDX декодированную форму, либо `Figure` декодирует адрес перед
  чтением файла. Решить по данным подвыборки до кода S6.
- **Источник `width`/`height` для `cover`.** Строка DEBT-B от 2026-08-27
  назначала источником S6; этот ADR его снимает. Решение — на гейте S8:
  мигрировать без `cover` либо S8 измеряет первую редакционную картинку сам.
- **Предпроверка читаемости.** S6 может прогонять каждый скопированный файл
  через `image-size` — ту же операцию, что выполнит `Figure`, — и отправлять
  нечитаемый файл в карантин сейчас, а не в смерть сборки потом. Цена —
  зависимость `image-size` в скриптах конвейера и лишняя секунда прогона.

## Рассмотренные альтернативы

- **`public/images/<slug>/` для мигрированных, как в ADR-0007.** Отвергнуто:
  общие файлы размножаются (обложка собрания — шесть копий), каждый `src` в
  теле переписывается, а таблица «легаси-путь → новый путь» становится второй
  истиной рядом с телом.
- **Оставить редакционные картинки абсолютными ссылками на `idrp.ru`, как
  товарные.** Отвергнуто: редакционное ядро журнала стало бы зависеть от
  жизни старого сайта, тогда как зеркало полно и файлы можно забрать сейчас.
- **Плоская папка с переименованием** (`public/images/legacy/<имя>` или имя
  по хешу содержимого). Отвергнуто: требует переписывания адресов, теряет
  происхождение, а легаси-файлы неизменяемы — хеш ничего не защищает.
- **Копировать легаси-корни целиком.** Отвергнуто: `/images/content` содержит
  911 файлов, из которых тела цитируют 346; лого, служебная графика и
  миниатюры в контенте не нужны, а лишние файлы не видны отчёту.

## Последствия

- Плюсы: адреса в телах не трогаются; дублей нет по построению; старые
  внешние ссылки на картинки продолжают работать на новом домене без
  редиректов; `Figure` не меняется; стадия S6 сводится к сверке и
  копированию; перепрогон идемпотентен.
- Минусы / компромиссы: публичное пространство нового сайта наследует три
  легаси-корня (`/images/content`, `/htm`, `/pages`) — мост B4 не должен
  перехватывать адреса, для которых есть файл в `public/` (в Next файлы
  `public/` обслуживаются раньше `afterFiles`- и `fallback`-rewrites, но
  `beforeFiles`-rewrites и middleware идут раньше всего — проверить при
  реализации B4); в `public/images/` живут две раскладки; полный перепрогон
  невозможен без зеркала; репозиторий тяжелеет примерно на 9 МБ при B5.
- Дальнейшие шаги: ревизия №4 декомпозиции B1 (раздел S6; критерий «Готово»
  п. 1); `config/media.ts` и файл стадии `copy_img`; строка в
  `scripts/migration/README.md`; строка в индексе `adr/README.md`; пометка в
  ADR-0007 «узел `public/images/<slug>/` уточнён ADR-0010»; строки DEBT-B по
  открытым вопросам.

## Триггеры пересмотра

| Триггер | Ожидаемое изменение |
|---|---|
| Миграция магазина: товарные файлы становятся доступны локально | Правило п. 1 распространяется на `/buy/content/products/...` тем же копированием с сохранением пути; абсолютные адреса в телах переписываются на локальные (чек-лист демонтажа шва) |
| Переезд контента в CMS с медиатекой (ADR-0003, триггер «не-технические авторы») | Пути становятся собственностью CMS; этот ADR замещается новым |
| Выключение `idrp.ru` до миграции магазина | Товарные картинки переносятся с сервера заранее — долг DEBT-B со сроком годности |
