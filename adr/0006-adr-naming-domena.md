# ADR-0006: Нейминг доменных сущностей — гибрид транслита и английского

- Статус: Предложено
- Дата: 2026-07-15
- Номер закреплён: 0006 (2026-07-25)

## Контекст

Домен журнала русскоязычный: рубрики («Житие», «Именины», «Добротолюбие»),
источники житий, церковные понятия (даты памяти, переходящие праздники).
`rubrics-taxonomy.md` подготовил два варианта нейминга (А — транслитерация,
Б — перевод) и оставил решение будущему ADR. Решение стало блокером шага A4
(типы домена и Zod-схема фронтматтера): значения union рубрик — это данные,
которые разойдутся по фронтматтеру ~1523 статей конвейером B1; менять их
потом — скрипт, но неприятный.

Давления, тянущие в разные стороны:
- легаси-слаги уже транслитом (`zhitiya-svyatih`, `imenini`) — непрерывность
  URL нужна для редиректов 301 и сохранения SEO-веса (ADR-0009);
- конвейер B1 сличает `type=4` (дамп) → рубрику (фронтматтер) → слаг (URL) —
  один алфавит на всей цепочке убирает класс расхождений и второй словарь;
- у части терминов перевод врёт или экзотичен: NameDay ≠ именины культурно,
  Philokalia — термин для специалистов;
- код читают и люди без русского; транслит универсальных слов
  (`den`, `mesyac` вместо `day`, `month`) — шум без пользы, что подтвердилось
  практикой при моделировании дат памяти в A4.

## Решение

Гибрид с критерием разделения: **транслит — там, где перевод теряет смысл;
английский — там, где транслит теряет читаемость.**

1. **Значения-данные** (значения union рубрик, источников житий — то, что
   пишется во фронтматтер и сверяется с легаси) — **транслит, snake_case**:
   `zhitie`, `imeniny`, `dobrotolyubie`, `russkiy_palomnik`.
   Мотив: непрерывность с дампом и слагами легаси; один словарь данных.
2. **Имена доменных типов** — **транслит, PascalCase**, по таблице
   `rubrics-taxonomy.md` вариант А: `Zhitie`, `Imeniny`, `Rubrika`,
   `ZhitieIstochnik`. Мотив: словарь предметной области должен совпадать
   с языком домена и данных (ubiquitous language).
3. **Имена полей и универсальные понятия** — **английский, camelCase**:
   `title`, `slug`, `cover`, `day`, `month`, `datePublished`, `legacyId`.
   Транслит в именах полей — только для непереводимых доменных терминов
   (`rubrika`, `istochnik`, `datyPamyati`).
4. **URL-слаги** — **транслит** (как в легаси): `zhitiya`, `imeniny`,
   `pritchi`. Детали маршрутов — ADR-0009.
5. Пограничные случаи (термин с приемлемым переводом и культурной нагрузкой,
   напр. смещение от Пасхи: `otPashi` vs `afterEaster`) решаются локально
   при написании, без пересмотра этого ADR; выбранное имя закрепляется
   использованием, синонимы не заводить.

## Рассмотренные альтернативы

- **Чистый вариант А (всё транслитом, включая поля)** — максимальный «один
  словарь», но имена универсальных полей (`den`, `mesyac`, `zagolovok`)
  нечитаемы и выглядят карго-культом; аргумент непрерывности на имена полей
  не распространяется (в легаси поля уже были англицизмами: `dt1_day`,
  `dt1_month`). Отвергнуто по живой пробе в A4.
- **Чистый вариант Б (всё переводом)** — код полностью читаем без русского,
  но: рвётся цепочка данных легаси→фронтматтер→URL (нужен постоянный
  словарь соответствий), а переводы части терминов врут (NameDay,
  SaintLife) или экзотичны (Philokalia). Отвергнуто: цена двух словарей
  выше выгоды.
- **Кириллица в идентификаторах/данных** — технически возможна местами,
  но ломает URL-практику, тулинг и конвейер. Не рассматривалась всерьёз.

## Последствия

- Плюсы: один алфавит на цепочке дамп → фронтматтер → URL (упрощение B1 и
  редиректов); домен говорит языком предметной области; универсальный код
  остаётся читаемым для любого разработчика.
- Минусы / компромиссы: код двуязычен по построению — смесь `Zhitie` и
  `datePublished` в одном интерфейсе непривычна на первый взгляд; граница
  «переводимо/непереводимо» местами вкусовая — возможны локальные споры
  (митигируется п. 5: решать на месте, закреплять использованием);
  разработчику без русского доменные термины придётся выучить (это цена
  любого национального домена, перевод её не устранял, а маскировал).
- Дальнейшие шаги: типы и схемы шага A4 следуют этому ADR; слаг-политика
  и редиректы — ADR-0009; при появлении новых сущностей (магазин,
  конфигуратор) — применять тот же критерий.
