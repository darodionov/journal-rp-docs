# ADR-00XX: Динамика главной страницы

- Статус: Предложено (черновик наставника; решения владельца от 2026-08-27:
  TZ = MSK, маршрутный TTL = 1 час; остальные пункты — предложения к ревью)
- Дата: 2026-08-27
- Номер: подставить следующий свободный в journal-docs/adr/

## Контекст

Главная-портал (шаг A13) верстается по макету `Glavnaya_Portal_2` на фикстурах
за портами; реальные данные приходят в B2 без правок разметки (критерий
«Готово» A13). Дизайн называет на главной поверхности, зависящие от времени:
блок дня, «Читальный зал» (в легаси — 3 случайные статьи), календарь-«колесо»,
лента событий; ревизией 2026-08-24 добавлена поверхность «ближайшие даты
памяти» (статьи с привязанной датой памяти, отсортированные по близости
к сегодня).

Рамки заданы ADR-0005: динамические края не живут в общем статическом HTML
(п. 7); путь чтения не использует request-scoped API (п. 8); эффективный
период ревалидации маршрута = минимум по периодам всех прочитанных данных
(п. 6); ревалидация ленивая, семантика stale-while-revalidate. Товарные ряды
(BookShelf, ProductSource) несут TTL ~1 час из товарного домена (ADR-0005
п. 5–6) — главная пересобирается примерно ежечасно независимо от календарных
блоков. Открытый пункт ADR-0005 «TZ виджетов зафиксировать при реализации»
для главной закрывается здесь.

Ключевое наблюдение проектирования: все календарные поверхности главной
зависят от момента, но не от читателя, и с точностью до суток. Такие данные —
детерминированная функция от даты: кэшируемы, тестируемы, не требуют JS.

## Решение

1. **Единый маршрутный TTL главной — 1 час, назначен явно** на маршруте
   (семантически `revalidate: 3600`; конкретная сигнатура — по текущей версии
   Next, ADR-0005 п. 12). Числом совпадает с товарным TTL, но не наследуется
   молча: явное назначение снимает риск «демонтаж товарных рядов оставит
   маршрут без TTL и заморозит календарные блоки».

2. **«Сегодня» — дата по MSK (Europe/Moscow)**, вычисляется на сервере при
   рендере/пересборке. Единственная точка вычисления — функция вида
   `todayMsk()` в `lib`; россыпь `new Date()` по компонентам запрещена.
   Дата в шапке остаётся клиентским островом с локальным временем читателя
   (A9, ADR-0005 п. 7) — это истина читателя, не сервера; данный ADR её
   не трогает.

3. **Дата передаётся в порты параметром.** Страница вычисляет `todayMsk()`
   один раз и передаёт в вызовы (`getUpcomingMemorialArticles(today, limit)`,
   `getReadingRoomArticles(today, count)`, …). Порты — чистые функции от
   (дата, корпус): детерминизм даёт кэшируемость, а тестируемость — «главную
   на 24 августа» можно отрендерить в тесте, передав дату.

4. **Все календарные поверхности — детерминированные функции от даты MSK;
   собственного механизма суточного обновления нет.** Обновление в полночь —
   бесплатное следствие часовых пересборок: 23 пересборки за сутки дают тот же
   результат, первая после полуночи — новый.
   - **Ближайшие даты памяти:** фильтр статей с датой памяти по индексу
     (в A13 — фикстурный адаптер), сортировка по расстоянию до `today`,
     топ N.
   - **Блок дня:** детерминированный выбор материала по дате (правило выбора —
     редакционное, фиксируется при реализации; техника та же).
   - **«Читальный зал» 2×2:** легаси-случайность заменяется детерминированным
     псевдослучайным выбором с seed = дата (`seed('2026-08-27')` → одни и те же
     4 статьи в течение суток). Читатель видит ежедневную ротацию, сервер —
     чистую функцию.
5. **Даты памяти — только фиксированные (месяц-день) в фронтматтере.**
   Переходящие даты (пасхалия) — вне скоупа: решается в арке C вместе
   с именинным кустом. Отложено осознанно, не забыто.

6. **Календарь-«колесо» — статичный серверный компонент**; подсветка
   «сегодня» — от того же `todayMsk()` (та же точность до TTL). Интерактив —
   при календаре именин в C3 (по плану).

7. **Лента событий и товарные ряды** — кэшируемые серверные фрагменты за
   портами, укладываются в часовой TTL. «Живые» события без деплоя (редактор
   добавил — сайт показал) — будущий первый клиент Postgres по ADR-0002;
   отдельное решение при возникновении потребности.

8. **Клиентских островов ради динамики главная не добавляет.** Острова на ней
   те же, что на статье: меню, дата в шапке, поиск-оверлей.

## Рассмотренные альтернативы

- **Суточный TTL (revalidate: 86400).** Точность полуночи не улучшает
  (минимум по фетчам всё равно час — товары), а при демонтаже товаров дал бы
  сутки залипания. Отвергнуто: часовой TTL и есть фактический режим маршрута.
- **Клиентский остров для календарных блоков.** Точность до секунды и TZ
  читателя, но цена — JS, мигание/пустой блок до гидрации, контент хуже виден
  поисковику; редакционной подборке достаточно суточной точности. Остров
  заслужен только для истины читателя (дата в шапке — уже есть).
- **SSR главной.** Рендер на каждый запрос ради данных, меняющихся раз в
  сутки; CDN из раздатчика становится прокси. Отвергнуто.
- **Точная полночная пересборка (cron / time-based revalidation).** Механизм
  ради выигрыша ≤1 часа точности; журналу не нужен. Отвергнуто; вернуться,
  если редакция потребует смену подборки строго в 00:00.
- **Сохранить per-request случайность «Читального зала» (как в легаси).**
  Истина на каждый запрос — некэшируема; потребовала бы остров или SSR.
  Seed датой даёт то же ощущение ротации бесплатно. Отвергнуто.

## Последствия

- **Плюсы:** ноль JS ради динамики; ноль собственных механизмов времени —
  вся «суточность» едет на маршрутном TTL; детерминизм всех выборок =
  кэшируемость + воспроизводимость в тестах; страница знает только порты —
  B2 меняет адаптеры, не разметку; открытый TZ-пункт ADR-0005 закрыт для
  главной (MSK).
- **Минусы / принятые компромиссы:** первый визитёр после истечения TTL видит
  прошлую версию (SWR); смена подборки — в течение ~часа после полуночи MSK,
  не ровно в 00:00; ревалидация ленивая — без трафика страница не обновится;
  читатель в другой TZ видит «сегодня» по Москве (для церковного календаря —
  осмысленный дефолт).
- **Условия пересмотра:** демонтаж товарных рядов TTL не ломает (назначен
  явно — п. 1); появление поверхности с потребной точностью < часа → она
  становится островом, либо маршрутный TTL осознанно понижается (правило
  минимума, ADR-0005 п. 6); переходящие даты — арка C; «живые» события —
  отдельный ADR при потребности.
- **Дальнейшие шаги:** фикстуры с датами памяти вокруг текущей недели
  (Claude Code), чтобы блок был живым на глазах; вёрстка A13 по этому ADR;
  в ADR-0005 — пометка к открытому пункту TZ («для главной закрыт
  ADR-00XX, MSK»); B2 реализует реальные адаптеры под те же сигнатуры.
