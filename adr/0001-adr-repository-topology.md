# ADR-0001: Топология репозиториев — раздельные код / документация / AI-обвязка

- Статус: Принято
- Дата: 2026-07-02

## Контекст
Журнал разрабатывается в одиночку с помощью Claude Code. Сетап определяют две цели:
1. Код приложения должен читаться так, будто его писал живой инженер — это сильный
   сигнал для портфолио и собеседований. AI-обвязка (CLAUDE.md, .claude/, логи задач,
   комментарии вида «сгенерировано AI») в истории кода этот сигнал подрывает.
2. Чистое разделение ответственности: код приложения, проектная документация и
   AI-обвязка для сборки — это три разных типа артефактов с разными жизненными циклами.

## Решение
Использовать три независимых git-репозитория плюс существующий репозиторий легаси как
read-only справочник, разложенные соседями внутри неверсионируемой папки-контейнера:

    workspace/
      journal/        код приложения        — чистый, «человеческий» вид
      journal-docs/   ADR, дизайн, брифы     — без кода и обвязки
      journal-ai/     CLAUDE.md, .claude/*    — «пульт управления» Claude Code
      legacy/         старый PHP-сайт        — read-only справочник

Операционная модель:
- Claude Code запускается из journal-ai/. Оттуда он загружает CLAUDE.md и .claude/,
  а до остальных репозиториев дотягивается через additionalDirectories в
  .claude/settings.json (доступ к файлам на чтение и запись).
- По умолчанию Claude Code не загружает CLAUDE.md из добавленных директорий, поэтому
  никакие правила и обвязка не протекают в journal/.
- journal/.gitignore защитно перечисляет CLAUDE.md, CLAUDE.local.md и .claude/, так что
  эти файлы невозможно закоммитить в репозиторий кода, даже если они присутствуют локально.
- Сообщения коммитов во всех репозиториях не содержат AI-атрибуции и co-author-трейлеров.

## Рассмотренные альтернативы
- Единый монорепозиторий с AI-артефактами в .gitignore. Наименьшее трение, и
  закоммиченный код всё равно был бы чистым — но это не удовлетворяет требованию
  физически раздельных, не смешивающихся репозиториев, а рабочее дерево смешивает
  ответственности.
- Документация внутри репозитория кода в /docs. Проще перекрёстные ссылки, но
  привязывает жизненный цикл документации к репозиторию кода и засоряет «человеческий»
  репозиторий.

## Последствия
- Плюсы: репозиторий кода стерилен, загрязнить его нельзя; ответственности чисто
  изолированы; обвязка развивается свободно, не затрагивая код и документацию.
- Минусы / компромиссы: кросс-репозиторная атомарность — изменение плюс его ADR плюс
  правка обвязки живут в трёх репозиториях и трёх коммитах; единого атомарного PR нет.
  Для соло-проекта это приемлемо; митигация: держать ADR (в документации) источником
  истины, ссылаться на номера ADR из сообщений коммитов в репозитории кода и пересмотреть
  эту топологию, если издержки координации перевесят выгоду.
- Дальнейшее: если трение мешает, свернуть документацию в /docs репозитория кода,
  сохранив обвязку отдельной (это по-прежнему обеспечивает цель №1).
